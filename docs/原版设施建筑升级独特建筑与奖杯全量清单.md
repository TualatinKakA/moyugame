## 2. 设施域统一状态机

```text
facilityVisible = 所属 Alignment／Proof／Faction 可用
                  AND 当前 R／A 未移除该形态

facilityPurchasable = facilityVisible
                      AND 当前主货币足够支付 geometric bulk cost

upgradeVisible = 当前设施形态可用
                 AND 行内建筑数量／Trophy／R 门槛已达到
                 AND A < 3（普通建筑升级系列）

upgradePurchasable = upgradeVisible
                     AND 本轮未持有
                     AND 当前阶段成本可付

uniqueFormVisible = 对应 Quest 已永久解锁
                    AND 当前派系／Alignment／R／A 符合
uniqueFormPurchasable = uniqueFormVisible
                        AND 本轮 UB Upgrade 成本可付
```

关键区分：

- Tier 4–10 的三套设施由本轮 Alignment 互斥选择；不是三套同时开放。
- 普通设施升级的数量门槛只负责自身显示，不要求先买上一号升级。
- A3 起普通建筑升级系列移除，但设施本体、UB 和其他系统仍在；Post-A Free 不得推翻 A3 移除。
- UB Quest 是永久购买，UB 形态是本轮购买；二者不可合并成同一个布尔值。
- UB 是原设施的形态替换，不额外增加一种可同时购买的独立建筑。

## 4. 建筑价格、批量购买与 Ascension

### 4.1 首价与递增

第 `x` 个同 Tier 设施的价格：

```text
price(x) = B * M^(x-1)
```

`B` 为首个价格，`M` 为建筑成本倍率。基础 `M=1.15`，减去对应升级的 flat reduction `C`：

```text
A0／A4：M = 1 + 0.15 - C
A1–A3：M = 1 + (0.15 - C) / (5 * A)
```

### 4.2 批量购买

从已拥有 `x` 个开始购买 `q` 个：

```text
bulkCost = B * M^x * (M^q - 1) / (M - 1)
```

`MAX` 必须求满足总价不超过当前资源的最大整数 `q`，不能先按显示单价乘数量。大数运算、浮点取整和边界 `q=0` 必须有黄金样例测试。

### 4.3 Ascension 分离规则

- A3 移除普通建筑升级，不删除建筑或 UB。
- A4 建筑成本倍率回到 A0 形式。
- 旧主货币升级在后续 A 免费，只修改升级成本，不降低设施数量门槛。
- 设施生产倍率的 Ascension Penalty 与价格公式分别计算。

## 5. 普通设施强化的关系规则

- 每个设施固定 23 个编号强化；同编号不同设施是不同 ID。
- 每行 Requirement 决定可见；价格不足只显示资源不足。
- 同系列升级可全部购买，编号相邻不构成购买前置。
- 购买只激活自身效果，不负责显示下一号；下一号由自身数量门槛独立显示。
- `Adds 1 Assistant` 等附加效果与产出 Buff 同属该升级，需原子生效。
- Pre／Post Ascension 效果和成本分列，不能用当前 A0 公式覆盖后期。

## 6. 独特建筑的两级链

```text
UB Quest 可见（R／派系／统计条件）
→ 永久购买 Quest
→ 本轮 UB Upgrade 可见
→ 支付本轮 UB 成本，替换原设施形态
→ UB1 开放 Research／Facility 接口
```

```text
A2／R116 UB2 Quest
→ 永久购买 Quest
→ 本轮购买 UB2
→ 开放对应 Faction Union
→ Union 后开放 10–12 强化
```

Astral 的 Nexus／Pavilions／Halls of Origination 虽属该派系首个 UB，也直接承担 Union 入口；Mercenary 三个 UB 使用对应 Alignment 和 Mercenary Encampment 链。所有 UB 的显式条件还需与全局 Research 入口同时满足。

### 6.2 UB 实现约束

- 形态替换后继续使用原设施数量、Tier 和建筑统计；不要额外生成一座同名建筑。
- 多来源 Nexuses／Pavilions 等仍是一个 UB 形态定义，但来源建筑 ID 和当前派系上下文必须保留。
- UB1 的 Facility 解锁与 UB2 的 Union 解锁是不同 Action。
- 退休后当前形态按本轮购买规则重置，永久 Quest 不丢失。
- 研究、Union 或前置派系失效时，效果是否可用按当前版本规则判断；不得自行添加已被官方 4.3.0 删除的 unusable 限制。
- 来源差异：Undercities 在 UniqueBuilding／UndeadFaction 为 1,750 Necropolises，BuildingUpgrades 的 UB 参考行写 2,500；本文采用两处一致的主页面条件 1,750，并保留此冲突供客户端复核。
- BuildingUpgrades 将 HoL 的 Burning Abysses 参考行命名为 Infernal Realms；实现必须使用独立 ID，不能覆盖 Demon UB1。Pavillons／Pavilions 等拼写差异只放 alias。

## 9. 设施 Trophy 的统一关系

设施 Trophy 与普通建筑升级是两条独立链：

```text
建筑数量／Facility 条件达成
→ Trophy 永久 unlocked
→ Trophy Count 增加
→ 若有同名 Upgrade，则该 Upgrade 可见并按本轮成本购买
→ Trophy／Upgrade 再作为 Hall of Legends、派系、研究或其他 Trophy 的输入
```

- Trophy 永久保留；同名 Upgrade 的本轮购买不随 Trophy 自动写入。
- 同名不同等级分别记录，不用名称覆盖。
- 无成本／无 Buff 标注的 Trophy 只作为达成标记，不生成伪购买按钮。
- 建筑 Trophy 的系列顺序是各等级条件，不与普通升级的 23 个编号混为同一组 ID。
- Vanilla 派系专属内容在 Prestige 上下文中的限制按原版掉落／派系规则执行；已获得 Trophy 不因此删除。

## 11. 设施域与其他系统的接口

| 外部系统 | 对设施域的输入／输出 |
| --- | --- |
| Alignment／Proof | 决定 Tier 4–10 的形态集合与 Hall of Legends 入口 |
| Faction | 决定派系设施、UB 派系上下文和部分 Trophy 条件 |
| Excavation／Quest Artifact | 提供 Prestige／Research／后期 UB 的前置 |
| Research | UB1 的全局入口；Facility 解锁后继续开放对应研究 |
| Union | UB2／Astral UB 的后置，再开放派系 10–12 强化 |
| Trophy | 提供 Trophy Count、同名 Upgrade、HoL 基础产出和后续前置 |
| Spell／Challenge | 提供动态产出、自动点击、目标建筑和 UB 解锁统计 |
| Bloodline／Lineage／Set／Legacy | 通过显式 Effect 修改设施数量、产出、计数或形态效果 |
| Ascension | 修改成本、产出惩罚、普通升级可用性和旧货币免费规则 |
| Reset | 清除本轮建筑、普通升级和 UB 购买；保留永久 Quest／Trophy |

跨域效果只能引用设施稳定 ID 和 Effect Group，不能复制一份同名设施或修改其基础数据。

## 12. 推荐配置结构

```yaml
id: building.farm.upgrade.1
kind: buildingUpgrade
building: farm
visible:
  all:
    - { buildingOwned: { id: farm, value: 5 } }
    - { ascensionBelow: 3 }
purchase:
  costsByAscension:
    pre: { coins: "200" }
    post: { coins: "0" }
effects:
  pre: [{ stat: building.production, operation: multiplyPercent, value: 100 }]
  post: [{ stat: building.production, operation: multiplyPercent, value: 7.18 }]
  shared: [{ stat: assistants.count, operation: add, value: 1 }]

```
