# v1.0.2 Patch Plan

## 版本目标

修正《无限工时》当前实现中与 Realm Grinder **4.3.24 / Steam build 26618872** 已确认冲突的 Assistant FC、Goblin’s Greed、Green Fingers Discount、GB7、FC chance 和 RNG 规则，并为后续持续复刻原版内容保留稳定边界。

本补丁采用**最小侵入、复刻兼容方案**：

- 不重写游戏引擎，不新增第三方依赖。
- 复用现有内容定义、事务、派生缓存、调度器和选择器。
- 在现有模块内增加少量辅助函数，不建立新的服务层。
- 只修改已有源码和测试，不新增脚手架。
- 对当前内容的简化必须集中在明确接口内，不能散落在结算代码中。
- 未核实的 Goblin 8、Royal Exchange、AN4／EL7／UD7／DM2、AN5 不在本补丁中猜测性修改。

### 后续复刻兼容约束

1. Assistant 使用原版语义的运行时 tick 累计器，不以 `floor(run.time)` 代替。
2. 派生法术走通用 `duplicateSpell` 调用链，不把 Tax 简单折成金币乘法。
3. GFD 产出快照、有效 Gems、Gem Bonus、周期时间均通过小接口取得。
4. RNG 补齐原版范围函数，持久化策略由内容元数据驱动。
5. 上述接口当前可以只有一行实现，但后续增加原版内容时不得再改写主结算流程。

## 一、先实现共用 FC 缓存，避免重复改造

### 修改位置

- `src/systems/runtime.js`
- `src/systems/state.js`
- `src/ui/app.js`

### 最小实现

在 `createGameRuntime` 内增加一个**不写入存档**的数值缓存 `factionCoinCache`，并增加两个内部函数：

```text
queueRandomFactionCoins(amount)
flushRandomFactionCoins(mode)
```

缓存只保存总量，不按 Assistant、Greed、离线来源拆成多个缓存，否则会产生与原版不同的分配结果。事件来源统一使用 `source: 'randomCache'`；UI 改为监听该来源，不再假设每次 flush 都来自 Assistant。

```text
queueRandomFactionCoins(x):
    若 x 为有限非负数，则 factionCoinCache += x

flushRandomFactionCoins(mode):
    cache = factionCoinCache
    若 cache <= 0，返回

    entries = 当前合格 FC 派系
    N = entries.length
    若 N == 0，清空缓存并返回

    若 cache > 100:
        each = floor((cache - 100) / N)
        cache -= each * N
        对每个派系 grantFactionCoins(each)

    remaining = floor(cache)
    重复 remaining 次:
        使用现有 chooseFactionCoin 选择一个派系
        grantFactionCoins(1)

    factionCoinCache = 0
```

`grantFactionCoins` 在入账前执行 `Math.floor(amount)`，保留现有余额、found 和事实事件逻辑。手动点击仍直接入账，不经过缓存。

派系池和选择仍由内容定义驱动；后续加入 Underworld 时只修改合格池数据及 `getRandCoin` 映射，不改变缓存和入账函数。

### 调用时机

- Assistant 在线、Assistant 离线、Greed 和其他 `factionCoin.randomEligible/randomUnlocked` 奖励只调用 `queueRandomFactionCoins`。
- 每个**在线** `tickSimulation` 末尾 flush。
- 离线分段结算不 flush；下一次在线 tick 再 flush。
- 新游戏、读档、退休、投胎时缓存清零。
- 缓存属于运行时瞬态，但必须纳入事务回滚快照，避免失败事务残留缓存。

### 为什么这是最简方案

共用入口可以同时修正 Assistant、Greed 和离线 FC 的派系分配、整数入账与 found 时机，避免在三处复制同一套分配代码，也为后续其他原版 FC 来源提供同一接入点。

## 二、Assistant FC：使用运行时 30-tick 累计器

### 修改位置

- `src/systems/runtime.js`
- `src/systems/derived.js`

### 在线累计器

增加运行时瞬态 `assistantTickAccumulator`，不新增 timer、scheduler 任务或存档字段：

```text
assistantTickAccumulator += min(delta, 1/3) × 30
seconds = floor(assistantTickAccumulator / 30)
assistantTickAccumulator -= seconds × 30
```

累计器同时保留整 tick 和帧内小数余量；只有 `offline=false` 时推进。新会话和读档时初始化，失败事务随其他运行时瞬态一起回滚。离线 timeWarp 不消费在线累计器。

不能长期使用 `floor(timeAfter)-floor(timeBefore)` 替代，因为后者会在 timeWarp、读档和特殊时间修正后产生不同边界行为。

仅在 `seconds>0` 时执行一次：

```text
p = assistants × fcChance × seconds
n = floor(p / 100)
remainder = p - n × 100

若 commonFactionCoinRandom() × 100 <= remainder:
    n += 1

queueRandomFactionCoins(3 × n)
```

随后由在线 tick 末尾统一 flush。删除 Assistant 公式中的 `0.2`、连续 delta 平分和 `assistantFactionCoinMultiplier` 参与计算。

通用 `assistantFcMult` 字段可暂时保留以兼容内容注册和旧测试构造，但不再进入原版 Assistant 公式，避免扩大重构范围。

### 离线

离线不推进在线累计器，也不调用在线随机逻辑：

```text
amount = round(assistants × fcChance × seconds / 100)
amount = round(applyOfflineFactionCoinModifiers(amount))
queueRandomFactionCoins(amount)
```

当前尚未实现 Elven 4，因此保留离线修正函数入口，不新增无关派系内容。

离线报告增加 `factionCoinsPending`，表示已进入缓存、尚待下次在线 flush 的数量；`factionCoinsFound` 仍只报告实际入账，避免把 pending 冒充 found。

### 选择器与 UI

`src/systems/runtime.js:505-516` 的 Assistant 每秒数值改为**在线期望速率**：

```text
3 × assistants × fcChance / 100
```

`perFaction` 若保留，只能标记为期望值，不能继续表示实际等额分配。

## 三、Goblin’s Greed：只改现有定义和通用奖励入口

### 修改位置

- `src/content/definitions/spells.js`
- `src/systems/runtime.js`
- `src/systems/derived.js`

### 内容公式

```text
FC 数量：
80 + 2.25 × ln(10 + getEffectiveGems())^2.25

持续产出 Buff：
30 + 3 × ln(1 + x)^3
```

当前 `getEffectiveGems()` 只返回 `resources.gems`，但所有需要 Gems 的原版公式必须从该接口读取，后续有效 Gems 效果只需修改接口实现。

`x` 继续使用本轮 found；Avarice Drive 的 R 周期切换留待对应内容实现时处理，本补丁不新增挑战系统。

### 结算方式

`applyActions` 遇到随机 FC 资源时，不再立即 `chooseFactionCoin + grantFactionCoins`，改为 `queueRandomFactionCoins(amount)`。

这样可获得以下结果，而无需给 Greed 编写专用逻辑：

- 施法时不直接消耗派系 RNG。
- 不再整笔随机给一个派系。
- found 不在施法事务中立即增加。
- 下一次在线 tick flush 后，派生缓存自动通过现有依赖失效机制重算。

## 五、Green Fingers Discount：集中快照，分离在线与离线结算

### 修改位置

- `src/content/definitions/factions.js:134`
- `src/systems/runtime.js:252,383-409,490-493`
- `src/systems/state.js:139-145`

### 周期统计接口

增加小接口：

```text
getTimeStat(scope):
    当前 scope='r' 时返回 state.stats.r.time
```

GFD 及后续原版公式不得直接散落引用 `stats.r.time`；有效计数和周期规则后续集中在该接口调整。

### 在线产出快照

增加唯一入口：

```text
getGreenFingersCoinBonus({ state, derived, offline=false, real=true })
```

当前实现仍保持轻量：

```text
buildingPart = derived.buildingProduction
assistantPart = derived.assistantProduction
timeFactor = 1 + 0.01 × getTimeStat('r')^0.8
return buildingPart + assistantPart × timeFactor
```

后续加入原版 real production、offline 标记和来源专属修正时，只扩展此函数，不改 GFD 触发器。

保留现有 `timers.tasks.greenFingersDiscount`，基础间隔改为 120 秒。每次在线 tick 最多触发一次，不循环补发：

```text
coinBonus = getGreenFingersCoinBonus(...)
roll = nextDoubleRange('greenFingersDiscount', 1, 1500)
reward = roll × coinBonus
dueAt = 当前 run.time + 120
```

roll 为连续 Number，不取整。挑战后的 30 秒规则通过同一个 interval helper 预留，当前没有对应挑战内容时不虚构解锁。

### 离线

在 `settleOffline` 开始时只抽取一次：

```text
multiplier = 1 + 0.01 × nextDoubleRange(
  'greenFingersDiscount', 2000, 10000
)
```

将该倍率传入离线分段的 production 计算；`tickSimulation(offline=true)` 不执行在线 GFD 到期逻辑。离线结束后将 timer 重置为当前时间起算的 120 秒。

这样只需给离线 production 增加一个乘数参数，不需要重放 N 次在线事件，也不需要另建离线任务队列。

### 旧存档

读取旧 GFD timer 时将剩余时间限制到最多 120 秒，避免旧版 600 秒计时在更新后继续残留。

## 六、GB7：使用通用派生法术调用链

### 修改位置

- `src/content/definitions/factions.js:130`
- `src/systems/runtime.js:280-303`

保留“非 Tax 施法后派生免费 Tax”的入口，将固定一次改为：

```text
times = 1 + floor(1.5 × ln(1 + derived.manaMax / 1000)^1.5)
```

增加通用内部函数：

```text
duplicateSpell(tx, spellId, times, {
  free: true,
  sourceId,
  preserveActiveSpells: true
})
```

GB7 只调用：

```text
duplicateSpell(tx, 'taxCollection', times, {
  free: true,
  sourceId: 'goblin-7',
  preserveActiveSpells: true
})
```

`duplicateSpell` 负责：

- 以 `times` 增加派生法术施法统计。
- 不支付 mana，不重新检查手动施法入口。
- 通过同一法术效果执行路径应用 `castActions`／等效 `onEffect`，不能只把金币乘 `times`。
- 使用事务内递归保护，派生 Tax 不再次派生 Tax。
- 不修改 Greed 或其他 active spell timer。
- 发出带 `sourceId` 和 `times` 的免费施法事实。

当前 Tax 只有金币动作时，结果应与批量结算相同；后续 Tax 增加统计、强化或特殊效果时仍自动走完整链路。

同步更新升级描述为“根据最大精力派生免费工资结算”。

## 七、RNG：原版范围函数与元数据驱动持久化

### 修改位置

- `src/core/rng.js`
- `src/systems/state.js`
- `src/systems/persistence.js`
- `src/systems/runtime.js`
- `src/systems/content-registry.js`

### 核心算法

保留现有 `seed + streams + calls/value` 数据结构，只替换核心递推：

```text
value = (16807 × value) mod 2147483647
result = value / 2147483647
```

JS 中该乘法最大值低于 `2^53`，可直接安全计算；无需引入 BigInt。

保留 `mixSeed` 作为项目确定性种子的初始化方式，但将结果规范化到 `1..2147483646`。旧存档中的越界 value 在首次抽取时规范化，不声称旧存档能够追溯还原为原版历史序列。

### 范围函数

在现有 `src/core/rng.js` 内补齐，不创建 RNG 类层次：

```text
nextInt(stream)
nextDouble(stream)
nextIntRange(stream, min, max):
    min -= 0.4999
    max += 0.4999
    return round(min + (max-min) × nextDouble(stream))

nextDoubleRange(stream, min, max):
    return min + (max-min) × nextDouble(stream)

randRange(stream, min, max):
    与 nextDoubleRange 相同，不取整
```

现有 `drawRandom` 可保留为 `nextDouble` 的兼容包装，逐步替换调用点，不在本补丁之外扩大重构。

### 实例划分

- Assistant 余数、手动 FC 判定、共享派系选择改用同一个 `drops:factionCoin` stream。
- Greed 不建立独立掉落 stream。
- GFD 保留自己的 `greenFingersDiscount` stream。

### 元数据驱动持久化

为需要专用 RNG 的 Spell／Upgrade 增加可选内容字段：

```text
rngStream: 'greenFingersDiscount'
rngPersistence: 'saved' | 'transient'
```

默认无专用 RNG；显式声明 stream 而未声明策略时默认为 `saved`，通用 `drops:factionCoin` 固定为瞬态。

在内容编译时生成 stream→策略映射：

- 保存时只过滤瞬态 stream，不再逐个写死名称。
- 读档时按同一映射过滤无效或瞬态 stream。
- 新会话按现有确定性 seed 初始化瞬态 stream。
- 退休、投胎不清空内存 stream。
- `content-registry` 校验空 stream 名、未知策略和冲突声明。

当前只为 GFD 声明专用元数据；后续原版 Spell／Upgrade 增加专用 RNG 时只改内容定义。
