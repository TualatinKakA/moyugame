# 《无限工时》剧情与成就系统构建方案

文档版本：v1.0  
适用项目：`ttt2718/moyugame`  
目标：建立可增量扩展的首次剧情触发、成就分类、奖励计算、持久化和剧情展示系统。

---

## 1. 建设目标

系统需要同时满足：

1. 特定条件第一次成立时，自动触发剧情文本和图片；
2. 剧情触发时可同步发放一个剧情奖杯／成就；
3. 成就可分为剧情、游玩、挑战、秘密、活动等类别；
4. 游玩成就可以提供全局或特定系统 Buff；
5. 同一剧情和成就按设定范围只触发一次；
6. 刷新、离线结算、离职、转行和未来 Ascension 不应造成重复奖励或剧情丢失；
7. 多个同时触发的剧情需要排队展示，不能叠加多个弹窗；
8. 后续新增剧情、成就和奖励时，不需要修改游戏主循环；
9. 数值、剧情、成就、美术和界面可以相对独立开发。

核心原则：

> 剧情与成就在内容和界面上分类，在事件、存档和奖励底层保持统一。

---

## 2. 当前项目基础与缺口

### 2.1 已有基础

- `state.trophies` 可保存奖杯 ID；
- 已有部分法术奖杯条件和实际强化；
- 已有本轮、本次 R、本次 A 和全部历史统计；
- 已有 `schemaVersion`、内容包、R／A 进度和升阶历史；
- 已有本地保存、离线结算、导入导出和规范化函数；
- 已有按 R 切换的简易章节文案。

### 2.2 当前缺口

- 没有完整成就注册表、分类、进度和详情页；
- 没有剧情内容包、首次触发状态和剧情历史；
- 没有统一领域事件总线；
- 没有剧情图片、弹窗和展示队列；
- 实时日志目前只保存在内存中；
- 没有剧情与成就的统一关联及原子化保存；
- 没有覆盖刷新续播、重置去重和迁移的完整测试。

因此需要在现有基础上增加系统模块，而不是继续往按钮事件里堆判断。

---

## 3. 总体架构

```text
游戏行为／状态变化
        ↓
统一事件总线＋低频状态条件检测
        ↓
触发规则匹配（仅处理未触发内容）
        ↓
剧情系统                     成就系统
首次触发与队列               分类、去重、解锁账本
        ↓                     ↓
剧情文本／图片展示           奖励注册与数值效果计算
        ↓                     ↓
持久化 triggered／pending     保存 unlocked／unlockedAt
        ↓
统一存档与迁移
```

依赖方向必须单向：

- 引擎可以发出事件；
- 剧情和成就可以读取统计与状态；
- 成就奖励通过效果注册表参与数值计算；
- UI 不直接修改公式；
- 剧情文案不直接写数值结果；
- 图片资源不携带触发逻辑。

## 5. 统一事件标准

### 5.1 事件命名

采用过去式领域事件，表示已经发生的事实：

```text
building.purchased
building.upgraded
faction.joined
spell.cast
artifact.found
challenge.completed
abdication.completed
reincarnation.completed
ascension.completed
offline.settled
```

事件名称描述行为，不描述 UI。例如使用 `faction.joined`，而不是 `factionModal.opened`。

### 5.2 事件载荷

```js
{
  type: "building.purchased",
  at: 1234567890,
  data: {
    buildingId: "farm",
    quantity: 10,
    totalOwned: 25
  }
}
```

载荷只包含稳定 ID、数量和必要上下文，不传递 DOM 对象或整个派生缓存。

### 5.3 事件发射位置

事件应在状态事务成功后发出：

```js
const result = completeAction();

if (result.success) {
  emitGameEvent("faction.joined", { factionId });
}
```

不能在条件未满足、资源不足或操作失败时发成功事件。

---

## 6. 状态条件标准

### 6.1 行为条件与状态条件

- 行为条件：由领域事件直接触发；
- 状态条件：产值、点击、时间、法力、设施数量等持续统计条件；
- 混合条件：事件发生且状态达到要求。

### 6.2 条件注册

不允许在内容配置中直接写可执行 JavaScript。使用已注册条件 ID：

```js
{
  when: {
    all: [
      "runCoinsAtLeast100M",
      "currentFactionIsFairy",
      "onlyLowTierBuildings"
    ]
  }
}
```

条件注册表负责把条件 ID 映射到纯函数：

```js
conditions.runCoinsAtLeast100M =
  state => state.stats.run.coins >= 100000000;
```

### 6.3 检测频率

- 行为事件：立即检测；
- 状态阈值：建议每秒检测一次；
- 已永久触发内容：不再参与检测；
- 内容较多时按事件类型和系统建立索引；
- 不在每帧全量扫描所有剧情与成就。

## 7. 剧情内容配置标准

```js
{
  id: "first-abdication",
  title: "离职申请已批准",

  on: "abdication.completed",
  when: "always",
  once: "profile",

  paragraphs: [
    "您的离职申请已获批准。",
    "同时，您的调岗申请已自动通过。"
  ],

  image: "assets/story/first-abdication.webp",
  imageAlt: "离职证明上覆盖着一张调岗通知",

  achievementId: "story-first-abdication",
  priority: 100,
  tags: ["R0", "abdication", "tutorial"]
}
```

### 必填字段

- `id`：永久稳定；
- `title`：展示标题；
- `on`：触发事件或状态检测入口；
- `once`：触发范围；
- `paragraphs`：正文；
- `achievementId`：可空，但存在时必须指向有效成就；
- `priority`：同批展示排序。

### 图片字段

- 图片路径必须来自本地资源清单；
- 必须提供 `imageAlt`；
- 图片加载失败不能影响文本、成就或存档；
- 图片不参与触发逻辑。

---

## 8. 成就内容配置标准

```js
{
  id: "produce-1oc-abdicate",
  category: "gameplay",

  name: "循环终点",
  description: "在累计生产至少 1 Oc 后完成一次离职。",

  trigger: {
    event: "abdication.completed",
    condition: "runCoinsAtLeast1Oc"
  },

  visibility: "visible",
  once: "profile",

  reward: {
    type: "globalProduction",
    mode: "add",
    value: 8
  }
}
```

### 成就分类

- `story`：剧情见证与叙事标记；
- `gameplay`：产值、点击、建筑、技能、派系、离线等；
- `challenge`：明确限制条件与构筑挑战；
- `secret`：隐藏条件和特殊操作；
- `event`：节日与限时活动；
- `collection`：遗物、手册和长期收集。

### 奖励分类

- 无直接数值奖励；
- 全局产出；
- 指定设施或派系产出；
- 点击收入；
- 法力上限或恢复；
- 数字员工；
- 派系硬币；
- 离线收益；
- 资源置换；
- 解锁新系统、技能或槽位。

奖励必须引用效果注册表，不允许剧情系统直接修改最终产值。

---

## 9. 触发范围与重置规则

`once` 支持：

| 范围 | 含义 |
|---|---|
| `run` | 本轮一次，离职后可再次触发 |
| `reincarnation` | 本次 R 周期一次，转行后可再次触发 |
| `ascension` | 本次 A 周期一次，升阶后可再次触发 |
| `profile` | 当前存档永久一次 |

默认剧情成就使用 `profile`。只有明确的周期玩法内容才使用其他范围。

存档必须能判断：

- 条件是否已经触发；
- 内容是否已经展示；
- 成就已经领取；
- 当前周期是否允许再次触发。

---

## 10. 原子化触发流程

剧情触发与成就发放必须在同一状态事务中完成：

```js
function triggerStory(story) {
  if (hasTriggeredInScope(story)) return false;

  markStoryTriggered(story.id);
  unlockAchievementOnce(story.achievementId);
  enqueueStory(story.id);
  saveState(state);

  return true;
}
```

推荐顺序：

1. 检查当前范围是否已触发；
2. 标记剧情已触发；
3. 去重发放成就；
4. 加入待展示队列；
5. 记录触发时间；
6. 立即保存；
7. 再由 UI 展示。

不能采用“玩家关闭剧情后才发成就”，否则异常关闭可能导致状态不一致。

---

## 11. 剧情状态与展示队列

建议保存：

```js
story: {
  triggered: [],
  pending: [],
  seen: [],
  triggeredAt: {},
  history: []
}
```

字段含义：

- `triggered`：已满足首次条件；
- `pending`：已触发但尚未完成展示；
- `seen`：玩家已看过、关闭或跳过；
- `triggeredAt`：首次触发时间；
- `history`：可回看的剧情记录。

`history` 应限制长度或只保存 ID 和时间，不重复保存整段正文与图片。

刷新时：

- `pending` 不为空则继续展示；
- 不重复发成就；
- 不重复执行触发奖励；
- 玩家主动跳过也视为已展示，但保留回看入口。

---

## 12. 剧情与成就的关联方式

剧情节点只引用成就 ID，不重复定义成就奖励：

```js
{
  id: "story-first-abdication",
  achievementId: "story-first-abdication",
  title: "离职申请已批准",
  paragraphs: ["……"]
}
```

成就配置独立存在：

```js
{
  id: "story-first-abdication",
  category: "story",
  name: "第一次离职",
  description: "第一次发现离职与调岗可以同时生效。",
  reward: { type: "none" }
}
```

这样可以避免：

- 同一成就被定义两次；
- 剧情与成就的奖励内容不一致；
- 同一条件被重复计数；
- 后期补成就奖励时修改剧情文本配置。

## 13. 剧情成就与游玩成就的边界

### 剧情成就

适合：

- 第一次见证某段剧情；
- 发现某个组织层级；
- 阅读某份关键档案；
- 完成一次剧情反转；
- 解锁剧情收藏。

默认只作为剧情标记，不建议普遍提供全局 Buff。

### 游玩成就

适合：

- 达到产值、点击、设施或法力条件；
- 完成特定构筑；
- 使用某派系达到目标；
- 积累离线时间；
- 完成特殊操作或资源置换。

可以提供全局或特定系统 Buff，但奖励必须经过数值效果系统计算。

### 挑战与秘密成就

- 挑战成就更适合改变机制、增加槽位或强化部门；
- 秘密成就可提供特色奖励，但隐藏条件不能阻碍主线；
- 活动成就与活动存档应采用相同底层，不另建一套系统。

## 14. UI 与交互标准

### 14.1 剧情展示

使用统一弹窗或手机底部抽屉，包含：

- 标题；
- 图片与替代文本；
- 正文；
- 成就获得卡片；
- 继续／关闭按钮；
- 可选跳过按钮；
- 后续回看入口。

### 14.2 队列规则

- 多个剧情同时触发时不得叠加弹窗；
- 按 `priority`、触发时间和 ID 稳定排序；
- 当前剧情关闭后才展示下一条；
- 关闭后恢复原面板和焦点；
- 浏览器刷新不丢失待展示内容。

### 14.3 可访问性

- 弹窗有明确角色和标题关联；
- 支持 Esc、按钮和焦点管理；
- 不以悬停作为唯一信息入口；
- 图片失败时显示文本替代；
- 手机按钮保持可触控尺寸；
- 尊重减少动画设置。

### 14.4 是否暂停游戏

默认放置产出可以继续，剧情阅读不强制暂停。

只有以下情况才考虑暂停：

- 剧情要求玩家立即做选择；
- 挑战规则明确要求暂停；
- 继续计时会破坏剧情条件公平性。

是否暂停必须是明确配置，不能因弹窗出现而隐式改变产量。

---

## 15. 美术资源标准

剧情图片建议：

- 使用本地 WebP／PNG；
- 使用稳定资源 Key；
- 提供尺寸、替代文本和加载失败回退；
- 不在图片内写死关键解锁信息；
- 不使用未授权的原版图片；
- 手机端控制文件大小和裁切安全区；
- 图片加载不阻塞成就发放和存档。

建议资源清单：

```js
{
  key: "first-abdication",
  src: "assets/story/first-abdication.webp",
  alt: "离职证明上覆盖着调岗通知",
  width: 1280,
  height: 720
}
```

## 16. 存档结构与迁移

### 16.1 Schema 升级

加入剧情系统时，`schemaVersion` 从 2 升级为 3。

```js
{
  schemaVersion: 3,
  contentVersion: "r0-r3-v1",
  contentPacks: ["r0-r3"],

  progression: {
    reincarnations: 0,
    ascension: 0,
    ascensionStartR: 0,
    ascensionHistory: []
  },

  achievements: {
    unlocked: {},
    unlockedAt: {},
    progress: {}
  },

  story: {
    triggered: [],
    pending: [],
    seen: [],
    triggeredAt: {},
    history: []
  },

  stats: {
    run: {},
    r: {},
    ascension: {},
    total: {}
  }
}
```

### 16.2 与现有 `trophies` 的关系

有两种可接受方案：

1. 保留 `trophies` 作为解锁 ID 列表，分类与奖励由注册表提供；
2. 新增统一 `achievements` 账本，并把当前奖杯 ID 迁移进去。

选择后必须保持单一事实来源，不能让两个字段长期各自维护且可能不一致。

### 16.3 迁移要求

- 当前 schema 2 存档自动补入空剧情状态；
- 现有 R／A、建筑、派系、技能、重置和设置保持不变；
- 不迁移 Demo 存档；
- 迁移前保留原始存档快照；
- 迁移函数必须可重复执行且不重复发奖；
- 图片和 UI 临时状态不进入存档；
- 后续新增成就配置不需要修改旧存档。

---

## 17. 性能与增量开发要求

- 已永久触发内容不再参加每帧检测；
- 按事件类型建立剧情和成就索引；
- 状态条件采用低频检测；
- 大列表使用分页、分组或虚拟化思路，避免一次渲染全部成就；
- 不为每个剧情单独写 UI 事件；
- 不为每个成就单独写存档字段；
- 新增奖励优先复用现有效果类型；
- 新系统加入时同步增加内容校验、迁移测试和浏览器测试；
- 剧情、成就和数值测试应能独立运行。

---

## 18. 反模式与禁止事项

禁止：

- 把剧情触发写死在某个按钮的文本或位置里；
- 用 DOM 是否可见作为唯一触发条件；
- 同一成就同时由两套系统保存；
- 弹窗关闭后才发成就；
- 剧情配置中直接执行任意代码；
- 每次游戏循环都扫描全部历史内容；
- 让图片加载失败阻止成就发放；
- 让剧情文本直接修改最终产值；
- 把完整剧情正文和图片数据重复写入存档；
- 在没有迁移测试的情况下修改成就 ID。

---

## 19. 测试与验收标准

### 19.1 首次触发

- 条件第一次成立时触发剧情和成就；
- 条件未满足时不触发；
- 失败操作不会误触发；
- 同一条件重复成立不会重复触发。

### 19.2 原子性

- 剧情和成就同时生效；
- 成就奖励只计算一次；
- 弹窗前刷新不会丢剧情或重复奖励；
- 存档失败后应有明确错误处理，不伪报已保存。

### 19.3 队列与回看

- 多个触发按稳定顺序展示；
- 关闭后进入下一条；
- 跳过仍保留成就；
- 已看剧情可回看；
- 回看不会重新触发奖励。

### 19.4 重置与迁移

- 离职、转行、升阶遵守 `once` 范围；
- 永久剧情不重复触发；
- 周期剧情只在新周期重新触发；
- schema 2 存档迁移后原有进度不变；
- 迁移重复执行不会重复发奖。

### 19.5 浏览器与手机

- 桌面与手机弹窗均可关闭；
- Esc、按钮、焦点和减少动画设置有效；
- 图片加载失败不影响文本和成就；
- 弹窗不会造成主页面意外滚动；
- 无控制台错误和资源 404。

---

## 20. 分阶段实施方案

### P0：标准冻结

- 固定事件名称、内容 ID 和触发范围；
- 固定剧情与成就配置格式；
- 固定成就分类、奖励类型和存档事实来源；
- 明确现有 `trophies` 的兼容方案。

### P1：事件与条件底层

- 实现统一事件总线；
- 在成功的购买、加入派系、施法、审计、离职和转行后发射事件；
- 实现注册式状态条件；
- 建立事件索引和低频阈值检测。

### P2：成就系统

- 实现成就注册、分类、去重和解锁账本；
- 接入奖励效果注册表；
- 完成成就列表、详情和进度显示；
- 将现有法术奖杯纳入统一配置。

### P3：剧情系统

- 实现首次触发、pending 队列和 seen 状态；
- 实现文本、图片、成就卡片和弹窗；
- 支持跳过、回看和刷新续播；
- 将当前 R 章节首次开放转为剧情节点。

### P4：存档与迁移

- 升级 schema 3；
- 迁移当前 schema 2 存档；
- 保留原始存档快照；
- 验证重复迁移不会重复发奖。

### P5：验收与增量扩展

- 完成单元、事件、队列、重置、迁移和浏览器测试；
- 验证手机布局和资源失败回退；
- 后续只需新增内容配置、必要的新条件或奖励函数。

## 21. 建议的首个垂直切片

先只做三个剧情节点：

1. 第一次点击；
2. 第一次购买设施；
3. 第一次离职。

每个节点分别验证：

- 文本与图片；
- 一个剧情成就；
- 首次触发去重；
- 弹窗队列；
- 刷新续播；
- 离职后的保留范围；
- 当前存档迁移。

其中“第一次离职”可以关联现有 `Rewind` 类游玩成就，用于验证：

> 同一事件可以同时驱动剧情展示和游玩成就，但成就只解锁一次，Buff 只计算一次。

垂直切片通过后，再批量加入派系、技能、审计、挑战和 R／A 剧情。

## 22. 最终构建标准

系统只有满足以下条件才算完成：

- 剧情、成就、奖励和 UI 的职责明确分离；
- 剧情与成就共用事件和解锁底层，但按类别独立展示；
- 首次触发、成就发放和保存是原子化流程；
- 刷新、离线、离职、转行和升阶不会重复发奖；
- 多个剧情可排队、跳过和回看；
- 剧情图片与文本解耦；
- 成就奖励通过统一数值效果系统生效；
- 存档只有一份解锁事实来源；
- 新内容可以增量添加，不需要修改主循环；
- 迁移、去重、队列、奖励和移动端测试全部通过。

最终目标：

> 一套事件与存档底层，支撑剧情成就、游玩成就、挑战成就、秘密成就和活动成就；剧情负责呈现，成就负责记录，数值系统负责计算奖励。
