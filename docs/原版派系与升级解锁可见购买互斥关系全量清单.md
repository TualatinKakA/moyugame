## 1. 覆盖范围与完整性声明

本文件覆盖原版常驻成长系统中的 **16 个派系（含 Mercenary）、180 个有 Mercenary Template 的派系强化、45 个基础 Treaty／Pact／Alliance、15 个 Union、Heritage／Advanced Heritage、65 个派系挑战、15 个血脉、独特建筑与研究设施链、264 个研究、法术等级、15 条 Lineage 及其 Perk、24 个 Quest Artifact、82 个 Lore Artifact 条目、13 个 Artifact Set、63 个 Legacy／Legacy Combo、46 个通用升级、615 个建筑升级／独特建筑参考行**。

不包含限时活动、纯付费 Gift、纯剧情文本和奖杯 Buff 明细；奖杯作为前置时仍保留其条件。奖杯奖励本身见 `docs/原版奖杯条件成本Buff与升阶修正全量清单.md`。

“完备”在本文中指：每个收录条目都能由 **本表通用谓词 ∧ 行内附加条件** 推出可见、购买／获得、后置开放和互斥结果。没有用“后续解锁更多内容”代替具体目标，也没有把价格当成可见条件。

## 2. 四种判定必须分开

### 2.1 定义

- `discovered(x)`：永久发现／解锁资格，例如任务已买、遗物已挖到、挑战已完成、研究已发现。是否跨重置由第 4 章决定。
- `visible(x, ctx)`：当前上下文是否渲染条目。`false` 表示整条隐藏；`true` 不代表能买。
- `purchasable(x, ctx)`：当前是否允许执行购买／选择。必须已经可见，并且满足条目条件、上下文、槽位、互斥、未持有和资源检查。
- `active(x, ctx)`：已购买效果在当前派系／ Ascension 是否生效。可购买不等于可生效；但官方 4.3.0 已删除大量“目标不存在即不可用”的旧限制，不能再自行添加 usable 限制。

统一实现：

```text
visible(x) = panelVisible
             AND eraAvailable
             AND contextVisible
             AND (discovered(x) OR discoveryPreviewVisible)

purchasable(x) = visible(x)
                 AND NOT ownedInPurchaseScope(x)
                 AND requirementsMet(x)
                 AND affiliationAllowed(x)
                 AND slotAvailable(x)
                 AND NOT excludedByCurrentChoices(x)
                 AND canPayAllCosts(x)

onPurchase(x): 原子扣费 → 写入 owned/discovered → 执行 unlocks → 重算依赖与 UI
```

### 2.2 UI 状态

| 状态 | 含义 | 典型例子 |
| --- | --- | --- |
| `HIDDEN` | 不渲染 | 未买上一派系 Tier 时的下一 Tier；A3 的建筑升级系列 |
| `LOCKED_VISIBLE` | 可见但条件未满足 | 可累计进度的研究 `!`；Dragon 解锁阶段在到达 R 要求前展示 |
| `UNAVAILABLE_CONTEXT` | 已发现但当前派系不能用 | 研究 `?`；与当前派系相同的 Lineage |
| `AVAILABLE_UNAFFORDABLE` | 条件已满足但资源不足 | 已显示的金币／Faction Coin 升级 |
| `PURCHASABLE` | 所有购买谓词通过 | 可点击购买 |
| `OWNED` | 当前购买作用域已持有 | 本轮已买升级 |
| `SELECTED` | 占用唯一选择槽 | Bloodline、Lineage、Artifact Set、Legacy 选择 |

**硬性禁止：** `canPayAllCosts=false` 不得把普通已解锁升级改为 `HIDDEN`；`requirementsMet=false` 是否隐藏必须按条目族的可见规则，不得全局一刀切。

## 3. 通用前置、后置与互斥规则

### 3.1 统计周期

- `This Game / Era`：当前 Abdication 周期；退休后重算。
- `This Reincarnation / This R`：当前 R；转生才清零。
- `Total / All Game`：跨重置累计。
- “首次／永久解锁”与“每轮重新购买”必须存不同字段。永久解锁不表示本轮效果自动激活。

### 3.2 依赖边类型

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| `UNLOCKS` | 获得永久资格 | Quest → Faction；Quest Artifact → Research Facility |
| `REVEALS` | 让下一条可见 | Trade Treaty → 本 Tier 三项；完成 Tier 1 → Tier 2 Treaty |
| `ENABLES_PURCHASE` | 已可见条目变为可买 | 研究发现条件完成；Union 已买 |
| `GRANTS_CONTEXT` | 提供系统入口 | Unique Building → Research；UB2 → Union |
| `EXCLUDES` | 选择后排除另一项 | 同轮 Base Faction、Bloodline、Lineage、Set |
| `CONSUMES_SLOT` | 非布尔互斥但受容量约束 | Research、Mercenary Upgrade、Legacy Container |
| `PREREQ` | 完成／购买前置 | Challenge N-1 → Challenge N；研究 A → 研究 B |

### 3.3 不能误判为互斥的关系

- 同一派系同一 Tier 的三个普通强化可全部购买，不是三选一。
- 同一建筑系列升级默认可全部购买；各行只受自身数量门槛，不要求先买上一号，除非行内明确写出。
- 研究之间只有显式 `Research X & Y` 前置和槽位／预算约束；不要根据编号猜测额外互斥。
- Challenge 的顺序是前置链，不是完成一个后锁定另一个。

## 7. 派系强化的可见与购买链

### 7.1 普通派系统一规则

设 `tierComplete(F,n)` 表示该 Tier 的 Treaty／Pact／Alliance 与三个普通强化均已购买。

| 条目族 | 可见条件 | 可购买条件 | 购买后置 |
| --- | --- | --- | --- |
| Treaty（Tier 1 首项） | 已加入 F 且当前 R／A 可用 | Faction Coin 成本可付 | 显示本 Tier 三个普通强化 |
| Tier 1 普通强化 | Treaty 已买 | 当前仍为 F；金币可付 | 三项全买且 Treaty 已买 → Tier 2 Pact 可见 |
| Pact（Tier 2 首项） | Tier 1 完整 | FC 成本可付 | 显示 Tier 2 三个普通强化 |
| Tier 2 普通强化 | Pact 已买 | 当前仍为 F；金币可付 | Tier 2 完整 → Alliance 可见 |
| Alliance（Tier 3 首项） | Tier 2 完整 | FC 成本可付 | 显示 Tier 3 三个普通强化；开放对应 Prestige／Research 等外部资格 |
| Tier 3 普通强化 | Alliance 已买 | 当前仍为 F；金币可付 | 12 项累计可触发 Champion；Tier 3 完整为 Union 的层级前置 |
| Union | Tier 3 完整 + 对应 UB2 已买 | 行内 FC 成本可付 | 显示 10／11／12 三个 Union 强化 |
| Union 强化 10–12 | Union 已买，满足行内 R／A | 金币／FC 可付；Mercenary 只能在允许的槽位选 | 16 项计入 Master Trophy |
| Heritage | 对应 Champion Trophy 永久获得 | 每轮 FC 成本可付 | 通用 Heritage 效果；不是 Tier 4 的前置 |
| Advanced Heritage | R116+；Master Trophy；对应 Lineage 30；对应 Spell 本轮 6h | 行内 FC 成本可付 | 与 Lineage／Faction Ruler 联动 |

Mercenary 选择派系强化时，不复制原派系的 Tier 显示链，而是使用 `MERC-SLOT`：对应 Contract 已买、槽位未占、强化符合 Alignment／Spell／Union 限制、未在其他槽重复选择、FC 类型与成本满足。Astral 强化只能进入 Upgrade 4／8／12／16；Astral Spell 只能由 Sorcery Contract 提供。

### 7.5 A4 成本覆盖与可见关系

A4 使用 Sapphire Coins，上表低阶主货币价格按 Ascension 通用规则处理；A4 的 Base／Prestige 强化改用独立公式，不能继续显示旧金币价格：

- Base 第 `x` 个强化：`1e51 * 1000^(x-1) * 1000^(0.5*floor((x-1)/3)*floor((x-1)/3+1))`。
- Prestige 第 `x` 个强化：同一结构，底数改为 `1e114`。
- Base 的 Treaty／Pact／Alliance／Union 分别为 `1 Qa / 1 Sx / 1 Oc / 1 Dc` 对应 FC；Prestige 分别为 `1 Oc / 1 Dc / 1 Dd / 1 Qad` 对应 FC。
- A4 Legacy 开放的三个强化仍支付其正常 A4 主货币成本；Legacy Container 免费或已购买不等于三个强化免费。
- 价格覆盖不改变 `FU-T1 → FU-T4` 的显示链。

## 10. Challenges：顺序可见、完成条件与奖励（65 项）

### 10.1 通用规则

- R2 显示 Challenge 面板；只显示各派系“首个未完成”的下一阶，后续 Tier 隐藏。完成 N 后显示 N+1，可在同一 run 连做多阶。
- 所有 Challenge 都要求对应 Faction；Challenge 2 另要求对应 Bloodline。Prestige／Astral 的指定 Base Faction 是必要条件，不是可替换建议。
- `visible(CH.n) = R2+ ∧ factionUnlocked ∧ CH.(n-1).completed ∧ eraAvailable`；`completable = visible ∧ 行内 Requirements ∧ 行内 Challenge`。
- 完成不是购买。奖励永久记录；实际 Perk 在当前派系符合时，由 Spell Upgrade／Challenge Power 等开关激活。
- Vanilla／Neutral／Prestige／Astral 的最终奖励及 Mercenary 的跨系统效果见各行“后置／适用”。不得把奖励误设为所有派系全局可用。

## 12. Unique Building、Union 与 Research Facility 前置链（92 个关系节点）

### 12.1 通用状态机

```text
UB Quest 可见（R／派系／统计门槛可预览）
  → 购买 Quest（永久）
  → UB Upgrade 可见
  → 每轮购买 UB（当前派系符合）
  → Research Facility 首项可见
  → 买 Facility 解锁项（永久）
  → 对应 Research 分支可用

A2 UB2 Quest → 购买 UB2 → Union 可见 → 买 Union → 10–12 强化可见
```

- UB Quest 的永久购买和 UB 每轮购买是两个 ID；合并会造成重置后研究永久丢失或重复永久解锁。
- “All faction upgrades bought”指该派系要求的完整集合，必须按当前版本 12／16 项口径明确计算，不能用模糊计数。
- Facility 可见不代表任意研究可买；仍需第 13 章的发现、点数、槽位和成本。

## 13. Research：发现、可见、购买、前置和槽位（264 项）

### 13.1 入口、发现和 Ascension 分支

```text
panelVisible       = 对应 Facility 已永久解锁 ∧ 当前 R／A 可进入 Research
contextKnown       = 当前 Base／Prestige／Merc 组合允许该研究
discoveryVisible   = panelVisible（可显示为锁定图标）
discovered         = 行内 Requirement 和显式前置研究已完成（永久发现）
eraEligible        = 当前 Ascension 允许该编号与类别
```

- `!`：当前派系可完成发现条件，显示进度；`?`：当前派系不能完成，仍可作为不可用图标显示。用户设置“隐藏不可用”只改变显示过滤，不删除依赖。
- 研究编号在低阶是点数门槛，在 A3+ 是 Budget 消耗；行内 `Research X & Y` 是额外前置，两者必须同时满足。前置研究不必在同一轮仍装备，除非行内明确写出。
- 发现永久，本轮装备／购买与槽位／预算另算。加载模板只能购买当前满足全部条件的项，不能绕过未解锁／点数／预算／槽位／成本。
- 官方 4.3.0 删除了“目标 Spell／UB 不存在就不可用”的一批旧 usable 限制；本文不擅自恢复这些限制。

| Ascension | 本轮购买谓词（均还需 `panelVisible ∧ discovered ∧ contextKnown ∧ 行内条件`） |
| --- | --- |
| A0／A1 | `branchPoints >= N ∧ freeSlot ∧ 行内 Coins 成本可付` |
| A2 | A0／A1 规则，另加：每分支普通研究最多 1 个；Faction-specific Research 不占这一限制 |
| A3 | 改为 Budget：`remainingBudget >= N`，购买消耗 N；不要继续要求低阶 `branchPoints >= N` 或旧槽位 |
| A4 | 沿用 Budget；编号 `<5000` 的 A0／A1 Research 为 `HIDDEN`，其余需 `remainingBudget >= N`；预算上限和获取按当前 A4 配置 |

研究点数／预算上限不是单个条目的可见条件：R100–174 旧口径 5000、R190–219 为 7000、R246+ 为 14000；它们限制可购买组合，不应把已发现的低编号研究重新隐藏，A4 明确移除规则除外。

## 14. Spell Tier 与 Autocast 的版本闸门

### 14.1 当前官方规则优先

官方 4.3.0 明确规定：

- Spell Tier Upgrade 由 Challenge 锁定；不再把旧 Wiki 的“达到法术活动时间公式”当作唯一解锁条件。
- 每个 Ascension 多开放一层：A0 可 Tier 1，A1 可 Tier 2，依此类推；历史已解锁的高层不重复锁定，但超过当前上限的层级不能施放。
- Tax Collection（Round Table）、Dragon's Breath、Catalyst、Twisting Nether、季节法术等属于官方列明的例外，不能套普通 Tier 规则。
- Reverse Autocast 不再是 Tiered Autocast 的前置，两者独立。
- 4.3.0 后 Spell Tier 还影响离线 FC；这不改变其可见／购买依赖。

```text
tierVisible(spell,n) = spellContextVisible
                       AND tierChallengeDiscovered(spell,n)
                       AND configuredActivityRequirementMet(spell,n)
                       AND n <= ascensionTierCap(A)  # 普通法术

tierPurchasable = tierVisible
                  AND 本轮尚未购买
                  AND Diamond／Emerald／对应 FC 成本可付

castableTier = min(已购买 Tier, ascensionTierCap(A), 其他显式加层效果)
```

Wiki `SpellTiers` 页的 R42／活动时间公式属于旧入口描述，但官方 2025-08 后续补丁仍提到 Tier Upgrade 的 activity time 提示，因此不能简单删除活动时间条件。安全模型是：**R／系统入口 ∧ 对应 Challenge 锁 ∧ 当前版本仍配置的活动时间要求 ∧ Ascension 上限**；旧公式不能在未核验时原样当成当前数值。当前实现应为每个 `(spell,tier)` 配独立 `challengeUnlockId` 和可选 `activityRequirement`，不要用一个全局计时器代替。官方后续补丁仍可能调整具体 Challenge／时间和成本，需按版本配置而不是硬编码旧表。

### 14.2 可见和购买的常见错误

- “已能看到 Tier 3”但 A1 上限只允许 Tier 2：应显示上限原因，不可购买／施放，不可静默扣除资源。
- “Challenge 已完成”但本轮未买 Tier Upgrade：永久发现保留，本轮效果未激活。
- “Reverse Autocast 未买”不能禁止 Tiered Autocast 出现。
- 法力不足只禁止施法，不应隐藏已解锁法术或 Tier。

## 24. 推荐配置结构与判定顺序

```yaml
id: research.S150
kind: research
panel: research.spellcraft
era: { minR: 16, allowedAscensions: [0,1,2,3,4] }
visibility:
  rule: RESEARCH_FACILITY
  facility: spellcraft
  previewWhenLocked: true
discovery:
  all:
    - { researchDiscovered: D10 }
    - { researchDiscovered: A105 }
purchase:
  all:
    - { branchPointsAtLeast: { branch: spellcraft, value: 150 } }
    - { freeSlot: spellcraft }
    - { contextAllowedBy: sourceRequirement }
cost: { coins: 1.296e152 }
scope: { discovery: permanent, purchase: abdication }
excludes: []
onDiscovered: [recomputeDependents]
onPurchase: [occupySlot, recomputeResearchDependents]
source: http://musicfamily.org/realm/ResearchList/
```

统一求值顺序：版本／R／A 过滤 → 面板入口 → 永久发现 → 当前派系上下文 → 条目可见规则 → 显式前置 → 唯一选择／互斥 → 槽位／预算 → 资源 → 原子购买 → 反向依赖重算。不要先检查价格再决定是否渲染。

## 25. 验收测试矩阵

每条自动化测试至少覆盖下列等价类：

1. **隐藏**：系统未开、上一 Tier 未完、R／A 不在区间。
2. **可见但锁定**：研究 `!`／`?`、Dragon R 前阶段预览、Challenge 下一阶条件未完成。
3. **可见但买不起**：条件已满足，分别缺 Coins、FC、Royal Exchange、Sapphire；仍保持可见。
4. **可购买**：全部谓词通过，原子扣费且只记一次 owned。
5. **购买后显示**：Treaty／Pact／Alliance／Union、Challenge、UB／Facility、Legacy 的后置逐项出现。
6. **互斥**：Base、Prestige、Astral、Bloodline、Lineage、Set、Legacy Combo 的选择冲突。
7. **槽位**：Research／Mercenary／Legacy 容量满时可见但不可选；增槽例外生效。
8. **重置**：永久发现保留，本轮 owned／选择清除，价格与统计周期正确重置。
9. **A3／A4 删除与重引入**：建筑升级 A3 隐藏；指定通用系列 A4 隐藏；Astral 在官方 A4 区间恢复。
10. **版本冲突**：Spell Tier 同时核验 Challenge、当前配置的活动时间（如有）与 A 上限；Bloodline 不要求 100  upgrades；Reverse 与 Tiered Autocast 独立。
11. **依赖图完整性**：所有 `prerequisiteId` 存在；除显式循环机制外无环；所有不可购买状态都有机器可读原因码。
12. **双向覆盖**：每个非根条目至少有一个入边或系统根；每个 `unlocks` 目标存在且确实重算。

建议原因码：`HIDDEN_SYSTEM`、`HIDDEN_ERA`、`HIDDEN_PREVIOUS_TIER`、`LOCKED_REQUIREMENT`、`WRONG_FACTION`、`WRONG_ALIGNMENT`、`SLOT_FULL`、`EXCLUDED_BY_SELECTION`、`ALREADY_OWNED`、`NEED_COINS`、`NEED_FACTION_COINS`、`NEED_ROYAL_EXCHANGE`、`NEED_ASCENSION`、`AVAILABLE`。

## 26. 版本冲突与禁止推断清单

| 主题 | 旧／Wiki 描述 | 高优先级修正 | 实现结论 |
| --- | --- | --- | --- |
| Bloodline | 100 个对应派系升级 | 官方 3.7.4 删除此要求；100 是 Bloodstream Trophy | R7 入口，不挂 100 升级锁 |
| Spell Tier | R42+ 活动时间公式 | 官方 4.3.0：Challenge 锁 + 每 A 一层 | 旧公式只作历史对照 |
| Reverse → Tiered Autocast | 旧前置 | 官方 4.3.0 删除 | 两个独立升级 |

| 部分通用系列 | 达到数量即可买 | 官方 4.3.0：A4 移除指定系列 | 加 A4 era filter |
| Astral | Wiki 常列 R125–219 | 官方 4.3.0：A4 重新引入 | 可用区间配置化 |
| Lineage Perk | 固定 L30／L40 与 R105／R139 | 官方 4.3.0：非对称 Schedule、每 A 上限 25、A3 Perk 6；后续交换 Perk | Wiki 表作底表，当前 Schedule 独立配置 |
