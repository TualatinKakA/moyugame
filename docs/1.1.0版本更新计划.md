# 1.1.0 版本更新计划：六 Vanilla 派系完整实装

> 计划日期：2026-11-19
> 代码基线：`ttt2718/moyugame` 的 `main`，提交 `f6459f7`
> 文档快照：仓库内三份“原版全量清单”（2026-11-17）及职场名称对照
> 目标：完整开放 Fairy、Elven、Angel、Goblin、Undead、Demon 六个 Vanilla 派系，并补齐它们直接依赖的设施、法术、强化、成就、统计、UI、存档与验收。
> 本文是开发计划，不是完成报告；除“现状”章节明确标注已实装的内容外，其余均为待办。
> 保真目标：复刻原版数值与联动，而非仅复用名称。任何未通过来源核对和黄金样例的条目都不得宣称“已与原版一致”。

## 0. 先给结论

1. **本版六派系是 Fairy／Elven／Angel／Goblin／Undead／Demon。** Titan、Druid、Faceless 属于 Neutral，不是“剩下四个 Vanilla”的一部分，本版不开放。
2. 当前代码已有 **17 种设施、391 项编号设施强化、Fairy／Goblin 的 18 项普通派系强化与 2 个派系法术**。另外四派系目前只有 FC 定义，不能加入，也没有普通强化和法术。
3. 完整六派系范围必须再补 **Hall of Legends（传奇档案馆）**。否则 Demonic Heritage、Hell Rush、Mathematician 等只能写成空效果。因此本版完成后应有 **18 种设施、414 项编号设施强化、6 项传奇档案馆 Bonus**。
4. 六派系本体还包括 **18 个加入／协作／战略协议节点、54 项普通派系强化、6 个派系法术、6 个 Champion Trophy、6 个 Heritage、6 个法术 Trophy 及 6 个同名强化**。
5. Elven 5 依赖 **Royal Exchange**；Elven 8 依赖自动点击与数字员工触发链；Angel、Demon、Undead 依赖“有效计数更多”、离线、分立场时间等新统计。这些通用机制必须先做，不能只上新卡片。
6. **原版 Trophy 与同名 Upgrade 是两个状态。** Trophy 条件达成后永久解锁；没有同名 Upgrade 的 Trophy 直接作为标记／计数生效；有同名 Upgrade 的 Trophy，其 Buff 不会随解锁自动生效，必须在当前 run 再购买同名 Upgrade。
7. 本版目标实装且与六派系／设施／法术直接相关的原版 Trophy 共 **427 项**：412 项设施 Trophy＋6 项 Champion＋6 项法术 Trophy＋Unitary、Mathematician、Spellfury 3 项 Secret Trophy。本版只实装 9 项同名 Upgrade（6 个法术强化＋3 个 Secret 强化）；其余 418 项不生成购买按钮。The Architect 按当前需求只保留 Trophy，其官方同名 Upgrade 不在本版范围内。
8. Union、10–12 号强化、Advanced Heritage、Lineage、Challenge、Spell Tier、Unique Building、Research、Neutral／Prestige／Mercenary／Astral 均不在 1.1.0 范围内，不能为了凑“完整”而跳过其原版前置。
9. **Misc 通用独立升级不能只保留 Gem Power。** 当前已有 3 项，本版直接新增 24 项，使完整可用的 Misc 达到 27 项；另有 9 项只登记离线点击／连续离线等依赖，不冒充完成。
10. **复刻必须通过第 18 章的来源与联动验收。** 当前文档是保真计划，不是已验证报告；Assistant FC、Goblin’s Greed 等阻塞项关闭前，只能称部分复刻。The Architect Upgrade 按需求排除，不列为阻塞项。

## 3. 统一实装规则

### 3.1 可见、购买、效果必须分离

```text
条目可见 = 系统入口可用 AND 当前派系／立场／R／A 符合 AND 自身门槛达到
条目可买 = 条目可见 AND 本轮未持有 AND 资源足够
Trophy 解锁 = 条件达成立即永久记录
同名 Upgrade 生效 = Trophy 已解锁 AND 当前 run 已购买该 Upgrade
```

- 金币或 FC 不足只显示资源不足，不重新隐藏。
- 建筑 23 档强化只看自己的数量／R 门槛，不要求先买上一档。
- 派系普通强化必须按 `Treaty → 3 项 → Pact → 3 项 → Alliance → 3 项` 分层显示。
- 当前部门改变或退休后，本轮派系购买清空；Champion 与其他 Trophy 永久保留。
- Heritage 的解锁权永久保留，但 Heritage 本身每轮重新购买；购买 Heritage 不要求当前仍属于该部门。
- 不得在游戏内向玩家展示“内容包、schema、占位、后续版本、当前只开放”等开发文案。

### 3.3 Ascension 与成本

- 旧主货币计价条目在后续 A 按通用规则免费；FC、Royal Exchange、Sapphire 等资源不因此免费。
- 普通建筑升级在 A3 起移除，不能显示为“免费仍可买”。
- 本版派系强化的 A4 Base 第 `x` 项主货币成本使用：`1e51 × 1000^(x-1) × 1000^(0.5 × floor((x-1)/3) × floor((x-1)/3+1))`。
- A4 Treaty／Pact／Alliance 分别为对应 FC `1 Qa (1e15)`、`1 Sx (1e21)`、`1 Oc (1e27)`。
- 普通 Heritage 在 A4 移除；法术 Trophy 强化的旧主货币成本 A1+ 免费，但 Trophy 条件和当前派系上下文仍需满足。
- 官方 4.3.0 将 Royal Exchange 容器改称 Royal Market，并明确其 bonus 脱离普通 Ascension penalty 体系；不得再对 Exchange 套用普通 A 惩罚。
- 免费只改成本，不绕过可见、派系、R／A 或购买前置。

## 8. Royal Exchange：Elven 5 的必要前置系统

**本系统为 1.1.0 的 P0 必做项；不做 Royal Exchange，Elven 5 与版本完成验收均不通过。**

职场名称建议统一为 **部门资源置换**；每个派系有独立购买项，例如“产品部资源置换”。玩家文案：**“消耗该部门影响力，本轮全部设施产出 +10%。同一部门连续置换时，下次价格按 1.1 倍增长。”**

| 规则 | 数值／实现 |
| --- | --- |
| 可见 | 对应 Vanilla 派系 FC 已开放；不因当前加入其他部门而隐藏非当前部门 Exchange |
| 单次成本 | `nextCost = 20 × 1.1^n`，`n`＝该派系本轮实际已购买次数 |
| 单次效果 | 全局 Exchange 加成加算 `+10` 个百分点 |
| 可重复 | 是；每派系独立计数和价格 |
| 批量购买 | 按连续成本求实际可买数量，禁止“当前价×数量” |
| 购买事务 | 报价 → 校验余额 → 扣 FC → 增加 bought → 更新统计 → 失效派生缓存 → 发事件；失败整体回滚 |
| 统计 | bought、effective bought、bonus% 分开；消费不增加 found，也不回扣 found |
| 重置 | 退休清空本轮购买与加成；Trophy 永久保留 |
| UI 警告 | 消耗当前 Base 派系 FC 时可配置警告；不阻止其他派系 Exchange |

成本取整必须由统一数值层并用原版黄金样例锁定。`n=0／1／2` 的未取整价格依次是 `20／22／24.2`，验收同时覆盖边界余额。六派系基础版不实现 Neutral／Prestige 组合币 Exchange，也不实现后续 Heavy Coins、Research 等修饰。

## 18. 原版保真规范与发布否决项

### 18.1 每条内容必须有可追踪来源

```text
sourceName / sourceUrl / sourceVersion / sourceExcerpt
requirement / statScope / cost / rounding
target / effectFormula / stacking / resetScope
verificationStatus / goldenTestId
```

`verificationStatus` 至少分为 `source-confirmed`、`client-verified`、`blocked`。只有来源文字而没有组合验证的条目不能借名称相似推成 `client-verified`。这些字段只供开发和测试使用，不进入玩家可见文案。

### 18.2 数值复核不止核对一行公式

- 基础值、指数、常数项、百分比还是百分点、加算还是乘算。

- 目标集合、空目标行为、是否排除自身、是否只影响非独特设施。
- 成本增长、批量购买、最终取整、Ascension 成本覆盖和系列移除。
- 与其他效果的先后顺序、退休／投胎清除范围、离线和在线是否一致。

禁止根据相邻档位、名称或“这样更平衡”推断缺失数值。黄金样例必须记录原版输入、输出、版本和来源；不能只拿本项目当前输出反过来当标准答案。

### 18.4 当前简化实现是发布阻塞项

以下现有行为只能作为工作占位，不能纳入“已复刻原版”结论：

1. **Assistant FC 的实际当前算法**：每个在线／离线结算段计算 `total = assistants × 0.2 × (fcChance/100) × assistantFcMultiplier × deltaSeconds`，再对当前 `N` 个合格派系逐一入账 `total/N`。例如 10 名 Assistant、10% chance、无其他倍率、六派系开放时，每秒总量为 `10×0.2×0.1=0.2`，每派系每秒增加 `0.033333…`；60 秒后总量为 12，每派系各 2。全过程不抽随机数，余额和四层 found 都接受小数。`0.2` 目前只有期望速率依据；实际判定间隔、余量、派系随机、取整和离线采样必须用原版源码或黄金样例锁定。不得用固定期望产出冒充原版随机过程。
2. **Goblin’s Greed 的实际当前算法**：每次施法先计算 `Q = 20 + ln(1 + gems)^3`，再用 `drops:goblinsGreed` 随机流按合格派系权重抽取**一个**派系，最后把整笔 `Q` 全部入账该派系。0 期权时 `Q=20`，六派系等权即每种各 `1/6` 概率获得全部 20；不存在六种各分 `20/6`，也不是逐枚抽 20 次。公式当前直接产生浮点数，没有额外取整。必须核实原版是整批选派系还是逐枚／分段分配，以及取整和来源修饰，再实现对应批量策略。
3. **Royal Exchange 取整和加成顺序**：公式可登记为 `20 × 1.1^n`，但最终取整、连续购买和 Ascension 行为需要客户端黄金样例。
4. **有效计数与时间消费者**：不能因英文写 `for all purposes` 就全局替换所有统计，也不能自行排除 Trophy；逐个以原版行为锁定消费者。
5. **传奇档案馆待复核项**：第 16 章的真实矛盾和资料缺项必须关闭，不得用推测公式补齐。

确定性 RNG 只负责让测试可重放，不能改变原版分布。可用聚合随机、二项分布或余量策略优化性能，但数学分布、事件边界和统计结果必须与原版一致。

### 18.5 完全复刻的发布门槛

只有同时满足以下条件，才可声称“本版数值和联动复刻原版”：

- 所有本版定义均有锁定版本来源；官方补丁增量已应用，快照统计与最新版本没有混用。
- 所有数值通过独立黄金样例，所有上表联动通过组合测试；没有只验证单条公式、不验证相互作用的情况。
- 第 16 章和第 18.4 节没有未关闭的阻塞项。
- 当前代码中已知简化已替换或有原版证据证明等价；测试预期值不得直接复制当前实现。
- 验收报告能按内容 ID 追踪到来源和测试。任何一项做不到，只能标注“部分复刻／待验证”，不能发布为完全复刻。
