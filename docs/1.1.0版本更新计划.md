## 3. 统一状态、统计和购买规则

### 3.1 四层状态

| 层级 | 本项目对应 | 主要内容和重置要求 |
| --- | --- | --- |
| run | `stats.run` 及当前 run 状态 | 当前建筑、普通 Upgrade、派系协议、Heritage、法术／Secret Upgrade、Exchange bought、共享 FC 缓存；退休清除，Trophy 保留 |

| Era | `stats.ascension` | Era found、法术活动、Era 建造等；Ascension 清 Era，total 保留 |

禁止把旧资料中的 `This Game` 机械替换成同一个周期。GB1、FR7、AN2、GB8 等使用 Era；EL3、EL6、Moon Blessing 使用 R 有效点击；EL5 使用 Era found；EL7 的有效点击参数按白名单使用 run FC。每条定义必须按 CSV 绑定真实输入。

FC 余额和 run／R／Era／total found 分开。消费只扣余额，不回扣 found；退休、投胎和 Ascension 各清对应层，不得用余额代替 found 历史。

### 3.2 可见、购买、Trophy 与同名 Upgrade

```text
条目可见 = 系统入口、派系／立场、R／A 与自身门槛均满足
条目可买 = 条目可见 AND 本轮未持有（Exchange 除外）AND 资源足够
Trophy = 原版条件达成后永久解锁
同名 Upgrade 生效 = Trophy 已解锁 AND 当前 run 已另行购买
```

- 资源不足只显示不可购买，不重新隐藏条目。
- 编号设施强化每档独立，不要求购买上一档；visible 读当前原始数量。
- 六个 Base 派系每轮互斥，加入前必须有对应 Good／Evil 立场。
- Trophy 解锁不自动发放同名 Upgrade 的 Buff；无同名 Upgrade 的 Trophy 只有标记、计数和前置作用。
- Heritage 的 Champion 解锁权永久，Heritage 本体每轮重购，不要求当前仍属对应派系；A4 移除普通 Heritage。
- 免费或成本覆盖只改成本，不绕过派系、R／A、Trophy 和其他前置。

### 3.3 原版 TrophyCount 与自定义 Trophy 隔离

建立稳定的 `originalTrophyIds` 集合，由原版 Trophy 对象派生 `TrophyCount`，不同档分别计数。Hall、EL9、DM5、Hellfire Blast 和 Hall Bonus 只读取该原版集合及原版明确允许的有效修饰。

本项目 `trophy.intro.*`、`trophy.first_*` 和其他自定义序章／派系 Trophy 可以保留独立 UI 与效果，但不得抬高上述原版公式输入。

## 4. FC 经济、Greed 与 RNG 底座

### 4.1 FC chance 与数量入账是两条链

FC chance 基础为 10，按原版显式来源加算／乘算，不 cap 到 100，也不存在通用 `10×R` FC 数量倍率。Gem Power 的 chance 公式为：

```text
floor(0.5 * (1.25 + y/4) * ln(1 + effectiveGems)^0.9)
```

其中 `y` 为已购 Gem Upgrade 数；没有 `/ln(10)`。chance 只进入概率聚合器，不能据此推断它会改变 Greed Q 或所有 FC 入账数量。

`addFactionCoins` 在每个派系入账前应用该函数显式支持的数量效果，再 `floor`，随后更新余额和各层 found。FC 入账不增加 clicks 或 clickCoins。

### 4.2 Assistant 在线精确算法

原版为 30 tick＝1 秒，单帧累计最多约 1/3 秒；每累计一个整秒批量输入 `A×seconds`，不是逐帧连续平分：

```text
A = getAssistantsNum()
p = getFactionCoinChance(true) * A * seconds
n = floor(p / 100)
remainder = p - n * 100
roll = 100 * random()                 // 每次在线批量消耗一个通用 FC RNG
if roll <= remainder: n += 1
if n > 0: cache += floor(n * 3)       // 判定后固定 ×3，只写共享缓存
```

Fairy Choir 改变有效 Assistant 数 A，不把每秒判定变成三次。每个在线批量只抽一次余数，派系分配另耗随机值。

### 4.3 Assistant／Greed 共享缓存与派系分配

常规合格池为六 Vanilla 派系；Underworld ready 后才加入 Dwarven、Drow。本版不得提前加入后两者。当前 Alignment／Faction 不缩窄池，也不提高当前派系权重。

```text
if cache > 100:
    N = 合格派系数                       // 本版常规 N=6
    each = floor((cache - 100) / N)
    cache -= each * N
    每个派系先入账 each
remaining = int(cache)
while remaining > 0:
    随机一个合格派系并入账 1
    remaining -= 1
cache = 0
```

`cache=100` 不进入超额等分；`cache>100` 才先等分。Greed 和 Assistant 合并后的缓存决定实际随机消耗和分配，不得各自整批随机给一个派系。缓存不保存，`softReset` 清零；新进程从 0 开始。

### 4.4 Assistant 离线公式

```text
x = round(getFactionCoinChance(true) * A * seconds / 100)
x = applyOfflineFactionCoinModifiers(x, A, seconds, offline)
result = round(x)
```

离线不逐秒抽随机、不使用在线固定 ×3。基础期望先 round，来源修正后再 round。EL4 的 +200% 只作用于离线来源乘区，即该部分 ×3，不把在线 Assistant FC 或 Greed Q ×3。

### 4.5 Goblin's Greed 精确顺序

```text
Q = 80 + 2.25 * ln(10 + effectiveGems)^2.25
Buff = 30 + 3 * ln(1 + selectedFactionCoinTotal)^3
```

- `ln` 为自然对数；Q 不在 `onEffect` 内整体取整，也不乘 `times`。
- `onEffect` 不直接抽派系，只把 Q 写入共享缓存，之后统一 flush、逐派 floor。
- Greed 先执行通用逻辑和写缓存，再建立 active，最后按原版入口派生 Tax；实际余额／found 在后续主循环 flush 才增加。
- 同次派生 Tax 看不到本次新增 found；flush 后，后续 Buff 才读取新值。
- 本版 Buff 的 selected found 按总报告结构化数据使用 **Era found**，不是 run found。
- 普通离线 timeWarp 不调用 Greed `onEffect`，不存在另一套离线 Greed Q。

### 4.6 GB7 派生 Tax Collection

```text
times = 1 + floor(1.5 * ln(1 + maxMana / 1000)^1.5)
```

派生 Tax 不耗精力、不递归触发自身或 Greed，按原版计入允许的施法统计，并保留 `free` 与 `sourceId`。Greed Drive 不会“被免费 Tax 打断”；本版 Greed Drive 也不是连续施法 Trophy。

### 4.7 RNG 与持久化

原版通用算法为 Park–Miller：`a=16807`、`c=0`、`m=2147483647`，`nextDouble=gen()/2147483647`；`randRange(min,max)` 为连续值，不取整。实现时按报告伪代码还原 32 位中间运算，不能继续用另一套 32 位混合算法宣称等价。

| 随机流／瞬态 | 保存规则 | 重置规则 |
| --- | --- | --- |
| 通用 FC RNG | 不保存，新进程重播 | 同进程 softReset 不清零、不重播 |
| 标记 `4W` 的 Spell／Upgrade 专用流 | 保存并非零恢复 | 按原版实例规则，不混入通用 FC 流 |
| 共享 FC 缓存 | 不保存 | softReset 明确清零 |
| GFD timer | 保存／读回 | timeWarp 清零 |

测试可注入确定性 seed，但不得改变分布、事件次数或持久化边界。`nextDouble()==1` 等极端端点只在需要逐位回放时另做隔离验证。

### 5.2 自动点击

FR4、EL1、Sun Blessing、Elven Heritage 和 R Power 等自动点击必须保留来源标签。自动点击可以产生点击收益并按原版触发 FC／Elven Luck，但不冒充人工点击；EL7 只改有效计数，不把真实点击事件乘以倍率。

六项 ClickingBase 还包含离线自动点击。若交付这些升级，必须同时实现其离线点击、FC 与 Elven Luck 来源规则，不能只实装 base click 加算。

### 5.3 timeWarp 与离线事件边界

- 相应 offline 分支在 `seconds<60` 时直接返回；上限为 `2,592,000` 秒＝30 天，超出截断并标记，不是 24 小时。
- 先建立离线上下文和产出快照，再聚合 FC、产出、自动点击与离线施法，最后清理相应 timer 并失效缓存。

## 8. Royal Exchange／Royal Market

### 8.1 不是“每枚独立 +10%”

令 B 为 bonus 池，E 为所有派系的**有效 Exchange 总数**，base 在六 Vanilla 基础版为 0.1，A 为当前 Ascension：

```text
B = 10 + EL5 + 其他已开放的明确 bonus 来源
R = B * E
E = 0: multiplier = 1
A = 0: multiplier = (1 + 0.01*R)^(0.7*base^0.7)
A > 0: multiplier = (1 + 0.01*R)^((0.7*base^0.7)/(1 + 2.5*ln(max(1,A))))
```

- 非当前派系的 Exchange 同样计入 E；不是逐派各算完整倍率再相加。
- EL5 的 `1.75*ln(1+EraFC_found)^1.75` 加入 B 的加法池；R1 等本版明确开放来源也按各自接口进入，不能写死 B。
- 不套普通 Ascension penalty，只使用上述 Exchange 专属 A 指数和明确来源。
- 本版不开放 Exchange Master／Lord／HighLord、Titan、Research、Challenge、Ruby 等后续来源。
- bought、effective bought、bonus 分离；退休清 bought／effective／bonus，found 不因消费回扣。

### 8.2 逐枚价格与批量事务

某派系本轮已买 n 枚，再购买第 q 枚（q 从 1 开始）：

```text
r = 1.1
C(q,n) = floor(20 * (1 - r^(q+n)) / (1-r))
price(q) = round(C(q,n) - C(q-1,n))
```

前三枚价格为 **20／22／24**，一次批量买三枚总价 66。批量购买必须逐枚报价、扣款、执行 `onPurchase`、更新 bought／统计／缓存；总价是逐枚价格之和，不是“当前价×数量”，也不是只对整批几何总额取整一次。事务失败整体回滚，成功后每枚效果立即可见。

UI 可显示六派系余额、有效总数、B、下一枚价格和最终倍率，但内部不得只保存一个线性“每枚 +10%”加成。

## 14. Green Fingers Discount（GB9／GFD）

### 14.1 在线

正常逐秒 `update()` 基础每 120 次触发；Goblin Challenge 1 后的 30 次周期及派生 10 次 Tax 属于未开放的 Challenge 内容，本版不得提前实现。每次 update 只加 1，触发后清零，不按错过次数循环补发。

令 P 为触发时的复合产出快照：

```text
P = getProductionPerTickReal(-1) * 30
  + getAssistantsMultiplierReal()
    * getResourcePerClickReal(assistant=true)
    * getAssistantsNum()
    * (1 + 0.01 * timeR^0.8)

randomBase = thisUpgradeRand.randRange(1,1500)  // 连续 Number
reward = randomBase * P
```

随机 base 不是整数秒；奖励包含设施产出和 Assistant 产出快照，并随 R 时间增长。使用 GB9 Upgrade 自己的专用 RNG，不使用通用 FC RNG。

### 14.2 离线

离线不是逐 120 秒重放在线奖励，而是对整个离线产出乘区只抽一次：

```text
roll = thisUpgradeRand.randRange(2000,10000)  // 连续 Number
offlineBonus *= 1 + 0.01*roll                  // 连续 21–101 倍
GFD timer = 0
```

即使离线 7,200 秒，也不能发 60 次在线奖励。无随机预览通过 `_noRandom` 禁止抽取；专用 seed 和 timer 按原版保存／读取规则处理。
