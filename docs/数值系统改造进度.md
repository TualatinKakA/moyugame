## 二、已经写好的内容

### 1. 纯计算快照

涉及文件：`src/systems/engine.js`

已实现：

- 新增 `computeSnapshot(state, context)`；
- 计算过程不修改 `state`，不写 DOM、`localStorage` 或随机数状态；
- 快照包含产出、点击、数字员工、法力、影响力发现率、建筑输出、来源和警告；
- 快照及嵌套数据被冻结，兼容代码仍可使用 `computeState()`；
- 删除计算过程中的 `state._derived` 回写；
- 存档规范化会剔除历史 `_derived`，派生缓存不进入存档；
- UI 的法力与产出数据改从快照读取。

### 2. 修订号与缓存

涉及文件：`src/core/state.js`、`src/systems/engine.js`

已实现：

- `state.revision` 和 `touchState(state)`；
- 购买、施法、重置相关操作及内容状态变化会推进修订号；
- 相同修订号且输入未变化时复用同一快照；
- 对时间、点击、工资、期权等动态公式输入增加依赖指纹，避免外部直接改字段后读取旧快照；
- 增加 `UPGRADE_BY_ID`、`BUILDING_UPGRADE_BY_ID`、`UPGRADES_BY_BUILDING`、`UPGRADES_BY_FACTION` 等索引；
- 非工作页不再在每个 Tick 重建整个面板。

### 3. 结构化 EffectSpec 与聚合

涉及文件：

- `src/content/r0r3/effect-specs.js`
- `src/systems/effects.js`

已实现：

- 为全部 11 个派系建立显式效果定义；
- 每个效果具有目标、操作、值、叠加组、阶段和来源；
- 设施升级、通用升级、派系、挑战、技能、资源置换和 R 增益统一进入效果收集流程；
- `EffectAggregator` 按固定阶段执行效果；
- 加算和乘算使用独立通道，同类可交换操作不受注册顺序影响；
- 重复 EffectSpec ID 不重复生效，并写入警告；
- 快照提供逐项 `sources`，可定位来源、阶段、操作、值和目标；
- 特殊机制通过显式 `special` 标记进入既有规则，不再从英文描述推断。

### 4. 安全公式层

涉及文件：`src/systems/formula.js`

已实现：

- 用受控词法分析、AST 解析和递归求值替换 `new Function`；
- 支持算术、幂、括号以及 `ln`、`log10`、`floor`、`ceil`、`round`、`min`、`max`；
- 只允许已经声明的变量和白名单函数；
- 语法错误、未知变量、未知函数及非有限结果直接抛出 `FormulaError`；
- 错误包含内容 ID、阶段、公式和变量上下文；
- AST 有容量受限的编译缓存；
- 不再把公式异常静默转换成 0；
- 对 GB6、UD7、DD3、DN9、DW3 的旧公式文本问题设置显式修复表。

### 5. 固定阶段与真实 R/A 上下文

涉及文件：`src/systems/effects.js`、`src/systems/engine.js`

已实现：

- 当前阶段顺序为：原始规则 → 数字员工 → 法力 → 设施基础 → 设施局部 → 全局 → 影响力发现率 → 点击 → 其他规则；
- 后一阶段读取已经生成的只读派生上下文；
- 删除旧 `computeState()` 的两轮全量计算；
- 公式上下文使用真实 `R`、`A`、`ascensionStartR` 和内容包；
- Grand Balance 等公式不再把 A 固定为 0。

### 6. 已修复的代表性原有问题

以下属于恢复原内容声明意图的纠错，不是新增玩法：

- UD9 的设施数量加成原先因数值提取失败而未生效；
- DN2 原先使用硬编码 0.02，现按内容声明使用 0.01；
- DD6、DW3 原先被误判为法力上限效果，现进入全局产出；
- 多个派系公式原先因目标文案歧义读取了建筑数量，现读取显式声明的数字员工、法力或其他统计；
- DD9 按“非独特设施”定义排除传奇工位；
- 多处缺少乘号或括号不匹配的公式不再静默失效。
