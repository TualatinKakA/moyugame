# 档案审计（Excavation）系统逻辑与原版限制对照

> 审查日期：2026-11-17  
> 当前代码口径：`main@4d0ee96`  
> 当前内容范围：R0～R3，另记录原版后续 R／A 门槛，避免后续扩展时漏掉前置规则。  
> 原版口径：[G00F's Not a Wiki](https://musicfamily.org/realm/) 的 Artifacts、Quest Artifacts、Lore Artifacts、Rubies、Factions 与各派系页面。Wiki 用于机制对照，不作为官方服务器实时版本号证明。

## 1. 文档目的与状态定义

本文同时记录：

1. 原版考古／审计系统的完整核心流程、公式、限制与重置关系；
2. 当前版本实际执行的代码逻辑；
3. 当前已对齐、未实装、过严和统计周期错误的项目；
4. 后续实施顺序与必须补充的验收测试。

状态定义：

- **已对齐**：当前代码与原版核心规则一致，不代表所有边界和后期修正均完成。
- **部分实现**：有入口或部分步骤，但流程链不完整。
- **未实装**：当前没有实际玩法逻辑；只有存档字段也算未实装。
- **过严**：当前增加了原版没有的限制。
- **口径错误**：本轮、本转生、全历史等统计周期使用错误。
- **产品开关**：仅控制入口显隐，不代表底层系统已完成。

当前 `main` 的审计导航按钮已被移除，属于**产品开关**。`src/ui/app.js` 与 `src/systems/engine.js` 中仍保留审计面板和部分引擎逻辑，但正常界面入口是否恢复，应与功能完整度分开评估。

## 2. 核心结论

当前版本已经实现：

- 考古永久解锁；
- A0 基础审计价格；
- 35% 影响力奖励；
- 第 5／10／15／20／25／30 次审计的六条中立线索；
- 三个中立部门解锁物；
- 地下通道与两个高级部门任务；
- 退休保留审计计数，转生重建为 0。

当前仍未形成完整原版流程：

- Survey Equipment；
- Lore Artifacts；
- 审计红宝石与一次性里程碑；
- Ruby Reset／Free Reset；
- 免费重置的清空金币与 90% 产出惩罚；
- Underworld Diplomacy 每轮购买；
- 后续任务遗物、研究遗物与 Ascension 价格修正。

当前明确存在：

- Proof of Neutrality 前置过严；
- Druid 的 100 万影响力统计周期错误；
- Drow 的 10,000 次施法统计周期错误；
- 高级部门影响力在任务完成后直接开放，跳过外交购买；
- `survey`、`rubies`、`excavationResets` 等字段尚未组成实际系统。

**特别说明：旧审查中“转生后仍保留 `excavationCount`”的问题在当前 `main@4d0ee96` 已不存在。当前 `reincarnate()` 不再复制该字段，会随新状态归零。后续文档和修复任务不得继续把它列为当前缺项。**

## 3. 统计周期与计数器口径

### 3.1 原版常用周期

| 原版措辞 | 含义 | 当前项目较接近的字段 |
|---|---|---|
| This Game | 当前一轮，退休后重置 | `stats.run` |
| This Reincarnation / Total | 当前转生，可跨多次退休 | `stats.r`；部分代码仍误用 `stats.total` |
| All Time | 跨所有转生 | `stats.total` 与专门的永久字段 |
| Current Excavations | 当前转生内、最近一次重置后的审计次数 | `excavationCount` |
| Max Count | 历史最高审计次数，转生后保留 | 当前没有独立、完整的对应字段 |
| Free/Ruby Resets | 当前转生或指定公式作用域内的重置次数 | `excavationResets` 目前只是未使用汇总字段 |

注意：当前项目的 `stats.total` 是**全历史**，不能看到原版写 `Total` 就直接映射到它。原版 `Total` 通常指当前转生；但 All Time 和明确跨转生保留的解锁例外必须逐项处理。

### 3.2 审计必须区分的状态

后续实现不应只保存一个计数器，至少要区分：

- 当前审计次数；
- 当前转生最高次数；
- 历史最高次数；
- 当前转生免费重置次数；
- 当前转生红宝石重置次数；
- 全历史审计红宝石获得数；
- 已领取的红宝石里程碑；
- 免费重置造成的本轮产出惩罚；
- 永久任务／遗物解锁；
- 每轮外交权限。

## 4. 原版完整流程总览

```text
达到 1B+ 期权与产值条件
        ↓
购买 Archeology Upgrade（永久）
        ↓
执行 Excavation
        ├─ 获得 Faction Coins（概率）
        ├─ 达到固定次数获得 Rubies（每颗全历史一次）
        ├─ 达到固定次数／条件获得 Quest Artifacts
        └─ 购买 Survey Equipment 后可获得 Lore Artifacts
        ↓
中立线索 → 中立部门解锁物 → Proof of Neutrality → 中立部门条约
        ↓
100 次审计 + 1e35 → Survey Equipment（永久）
        ↓
200 次审计 + 5e49 → Passage to the Underworld（永久）
        ↓
Dwarf／Drow Quest（永久）
        ↓
Underworld Diplomacy（R0～R2 每轮购买，R3 起永久）
        ↓
高级部门影响力、条约、Royal Exchange、Heritage
        ↓
更高 R 阶任务遗物、独特建筑、研究、 excavation resets
```

审计次数既推进奖励，也提高下一次审计价格。原版通过转生清零、Ruby Reset 和 Free Reset 三种方式控制成本曲线。

## 5. 考古解锁与基础审计

### 5.1 Archeology Upgrade

原版要求：

- 超过 `1B（1e9）` 期权；
- 产出超过 `10Oc（1e28）` 金币；
- 支付 `100Oc（1e29）` 金币；
- 整个存档只需购买一次，永久开放审计入口。

当前 `unlockArchaeology(state)`：

```js
if (
  state.unlocked.archaeology ||
  state.gems <= 1e9 ||
  state.stats.total.coins < 1e28 ||
  state.coins < 1e29
) return false;
state.coins -= 1e29;
state.unlocked.archaeology = true;
```

结论：**核心门槛已对齐，永久保留已对齐。**

### 5.2 原版价格公式

原版第 `x` 次审计价格：

```text
Cost = 1e27 ^ (0.75 ^ A) × M ^ (x - 1)
```

其中：

- `A`：Ascension 次数；
- `M`：审计价格倍率；
- `C`：固定减费升级之和。

```text
A0：M = 1 + 0.2 - C
A1+：M = 1 + (0.2 - C) / (5 × A)
```

当前公式：

```js
Math.ceil(
  1e27 * Math.max(1.01, 1.2 - reduction) ** state.excavationCount
)
```

结论：

- **A0 基础部分已对齐**；
- `1.01` 下限是当前数值保护措施；
- Ascension 基底修正未实装；
- A1+ 减费衰减未实装；
- 当前没有独立 current／max 计数结构。

### 5.3 影响力奖励

原版：

- 每次审计基础 35% 概率获得影响力；
- That Excavated Quickly 后提高到 40%；
- 基础奖励公式：

```text
1500 + 0.05 × (x - 1) ^ 2.75
```

`x` 为当前审计次数，奖励再应用对应影响力倍率。

当前 `excavate(state)` 在扣费并使次数加一后：

```js
if (nextRandom(state) < 0.35) {
  findFactionCoins(
    state,
    1500 + 0.05 * (state.excavationCount - 1) ** 2.75
  );
}
```

结论：**35% 概率和 A0 基础奖励已对齐；40% 后期强化未实装。**

当前候选影响力池为：

- 六个基础部门；
- 已购买完整解锁物的三个中立部门；
- 已完成任务的两个高级部门。

最后一项与原版不一致：高级部门影响力应由 Underworld Diplomacy 开放，而不是任务完成立即开放。

## 6. 审计红宝石

### 6.1 原版规则

第 `n` 颗由审计获得的红宝石所需审计次数：

```text
25 × n × (n + 1)
```

示例：

| 红宝石 | 所需审计次数 |
|---|---:|
| 第 1 颗 | 50 |
| 第 2 颗 | 150 |
| 第 3 颗 | 300 |
| 第 4 颗 | 500 |

限制：

- 每颗审计红宝石都是**全历史一次性奖励**；
- 审计计数被 Ruby Reset、Free Reset、转生或升阶清零后，不能重复领取同一颗；
- 红宝石在退休和转生后保留；
- 第 1、10、25、50 颗另有奖杯；
- 红宝石还可用于 Ruby Power、审计重置和活动内容。

### 6.2 当前状态

- `state.rubies` 会在退休／转生时保留；
- 没有按上述公式发放红宝石；
- 没有 `rubiesFoundByExcavation` 或里程碑领取集合；
- 没有第 1／10／25／50 颗相关审计奖励流程；
- 没有 Ruby Power 与审计红宝石消费闭环。

结论：**只有货币占位字段，审计红宝石系统未实装。**

## 7. 六条中立线索与三个解锁物

### 7.1 固定审计次数

| 次数 | 原版遗物 | 当前 ID | 当前状态 |
|---:|---|---|---|
| 5 | Ancient Stoneslab 1 | `titanClue1` | 已实现 |
| 10 | Fossilized Piece of Bark 1 | `druidClue1` | 已实现 |
| 15 | Bone Fragment 1 | `facelessClue1` | 已实现 |
| 20 | Ancient Stoneslab 2 | `titanClue2` | 已实现 |
| 25 | Fossilized Piece of Bark 2 | `druidClue2` | 已实现 |
| 30 | Bone Fragment 2 | `facelessClue2` | 已实现 |

当前使用 `n >= threshold` 并通过 `addArtifact` 去重；由于正常审计每次只增加 1，与原版固定次数奖励基本等价。

### 7.2 中立部门解锁物

| 解锁物 | 原版要求 | 当前状态 |
|---|---|---|
| Fragment of a Titan Statue | 两块石板、300 Halls of Legends、`1e30` 金币、25K Angel＋25K Goblin | 基本对齐 |
| Druidic Runestone | 两块树皮、**This Game 1M Faction Coins**、`1e30` 金币、25K Elven＋25K Demon | **口径错误：当前读取全历史 `stats.total.factionCoins`** |
| Octopus Shaped Spine | 两块骨片、**All Time 36 小时**、`1e30` 金币、25K Fairy＋25K Undead | 全历史时长口径基本对齐 |

Druid 应读取本轮影响力，而不是跨退休／转生累计值。Faceless 的 36 小时则明确是 All Time，不能误改成本轮。

### 7.3 Proof of Neutrality

原版：

- 收集任意一个中立部门的两件 Quest Artifacts；
- 支付 `10Qa（1e16）`；
- 完整中立部门解锁物是后续加入具体部门的另一层要求。

当前：

```js
state.artifacts.some(a =>
  ['titanUnlock', 'druidUnlock', 'facelessUnlock'].includes(a)
)
```

即要求已经购买完整中立部门解锁物，**比原版更严格**。

正确拆分应为：

1. 两条线索满足 Proof of Neutrality 的出现条件；
2. 具体部门解锁物满足该部门 Trade Treaty 的加入条件；
3. 不得把第 2 步提前作为第 1 步的前置。

## 8. Survey Equipment 与 Lore Artifacts

### 8.1 Survey Equipment

原版要求：

- 至少 100 次审计；
- 支付 `100Dc（1e35）`；
- 整个存档只需购买一次；
- 不计入普通已购升级；
- 购买后才开放 Lore Artifacts。

当前只有 `unlocked.survey` 字段，没有购买、校验、效果或 UI 流程，属于**未实装**。

### 8.2 Lore Artifacts 的通用逻辑

原版 Lore Artifacts 不是单纯的“达到次数自动获得”，每条可包含：

- R 阶要求；
- 当前部门或立场；
- 禁止叠加高级部门的限制；
- 建筑、技能、点击、时长、重置次数等条件；
- This Game／This Reincarnation／All Time 周期；
- 固定概率或公式概率；
- 发现后还需购买的升级成本；
- 套装、研究或后续遗物用途。

重要限制示例：

- 基础部门专属 Lore Artifact 在叠加 Prestige Faction 时可能不可获得，例如 Fairy 专属遗物在 Dwarven 叠加时不掉落；
- Rough Stone 只在每轮第一次审计有 2% 概率；
- Dawnstone／Duskstone 受本地时间段限制；
- Know Your Enemy 系列要求 Mercenary 和跨部门升级条件；
- Raw Emerald 使用本轮免费与红宝石审计重置次数计算概率。

当前没有通用的“条件 → 概率 → 掉落 → 去重 → 后续升级”规则框架，所有 Lore Artifacts 均未实装。完整逐条目录见原版 [Lore Artifacts](https://musicfamily.org/realm/LoreArtifacts)，条目清单可继续与项目现有内容对照表同步，不应只补几条示例就宣称系统完成。

## 9. 两类审计重置

### 9.1 Ruby Reset

原版：

```text
Ruby Cost = floor(x / 3000) + 1
```

- `x` 为当前审计次数；
- 支付红宝石后，当前审计计数归零；
- 不因此重新开放已领取的审计红宝石；
- 红宝石通常更值得投入 Ruby Power，是否重置由玩家选择。

当前未实装：没有按钮、价格校验、红宝石扣除、计数归零或重置统计。

### 9.2 Free Reset

原版开放条件：

```text
Required Excavations = 2000 + 50 × R + 500 × x
```

- `R`：当前转生数；
- `x`：当前转生已经进行的 Free Reset 次数；
- 达到所需审计次数后可执行；
- 执行后当前审计计数归零；
- 清空所有手持金币；
- 获得 90% 产出惩罚，直到退休或转生；
- 免费重置通常到约 R30 才具备实际可达性。

当前未实装：没有开放条件、重置计数、清空金币、产出惩罚或惩罚解除逻辑。

### 9.3 重置的永久性问题

无论使用哪种审计重置：

- 当前审计次数归零；
- 下一次审计价格从较低水平重新计算；
- 已发现任务／剧情遗物不丢失；
- 已领取的审计红宝石不可重复获得；
- 相关重置次数可参与后期遗物和公式；
- 免费重置与红宝石重置次数不应混为一个无类型字段。

当前 `excavationResets` 只是一个数值字段，无法支持上述区分。

## 10. 高级部门任务链

### 10.1 Passage to the Underworld

原版：

- 200 次审计；
- 支付 `50Qid（5e49）`；
- 只需购买一次；
- 解锁 Prestige Quests；
- 不计入普通已购升级。

当前 `unlockUnderworld(state)` 已检查 200 次和 `5e49`，并永久保留 `unlocked.underworld`，此层基本对齐。

### 10.2 Dwarf 任务

原版要求：

- Good Alignment；
- 800 Inns；
- 7,000 Buildings Owned（This Game）；
- 10,000 clicks（This Reincarnation）；
- 支付 `1e46` 金币；
- 各 10,000 Fairy、Elven、Angel Coins；
- 整个存档只需完成一次；
- 完成后解锁 Underworld Diplomacy，而不是直接获得全部高级部门权限。

当前建筑与点击周期基本对齐，但任务完成后直接把 `dwarfQuest` 用作高级部门影响力和加入资格。

### 10.3 Drow 任务

原版要求：

- Evil Alignment；
- 650 Dark Temples；
- 325 trophies；
- 10,000 spell casts（Total，即当前转生）；
- 支付 `1e46` 金币；
- 各 10,000 Goblin、Undead、Demon Coins；
- 整个存档只需完成一次；
- 完成后解锁 Underworld Diplomacy。

当前读取 `stats.total.spellsCast`，即跨所有转生全历史，属于**口径错误**。应使用当前转生口径，而不是全历史。

### 10.4 Underworld Diplomacy

原版：

- 前置为对应 Dwarf／Drow Quest；
- 每次价格 `1Qad（1e45）`；
- R0～R2 每轮都要购买；
- R3 起转为永久；
- 解锁高级部门 Faction Coins、Trade Treaty、Royal Exchanges 和 Heritage。

当前没有独立的每轮外交状态、价格或购买步骤，且 `coinFactions()` 在任务完成后立即加入对应高级部门影响力，属于**绕过原版限制**。

正确流程：

```text
Passage（永久）
  → Quest（永久）
  → Diplomacy（R0～R2 每轮；R3+ 永久）
  → 高级部门货币与加入资格
```

## 13. 当前代码执行逻辑

### 13.1 解锁考古

位置：`src/systems/engine.js` 的 `unlockArchaeology(state)`。

1. 检查是否已永久解锁；
2. 检查当前期权、全历史产值和手持金币；
3. 扣除 `1e29`；
4. 写入 `unlocked.archaeology = true`；
5. 标记状态变更。

### 13.2 执行审计

位置：`excavate(state)`。

1. 要求 `unlocked.archaeology`；
2. 根据当前 `excavationCount` 计算价格；
3. 检查并扣除金币；
4. `excavationCount += 1`；
5. 增加 `run/r/ascension/total` 四层 `excavations` 统计；
6. 以 35% 概率发放影响力；
7. 在新次数达到 5／20、10／25、15／30 时添加对应线索；
8. 检查相关挑战；
9. 标记状态变更。

当前没有在该事务中处理：

- 红宝石里程碑；
- Survey 后的 Lore Artifact 判定；
- 通用条件概率型 Quest Artifact；
- Ruby／Free Reset；
- 免费重置惩罚；
- 独立最高次数；
- 高级部门外交权限。

### 13.3 中立解锁物

位置：`unlockNeutralFaction(state, id)`。

1. 检查是否已解锁；
2. 检查两条线索；
3. 检查 Titan 建筑、Druid 影响力或 Faceless 全历史时长；
4. 检查 `1e30` 金币和两种影响力；
5. 扣除资源；
6. 添加 `${id}Unlock`。

其中 Druid 的全历史影响力口径需要改为 This Game；Faceless 的 All Time 不应跟着一起修改。

### 13.4 退休与转生

当前 `abdicate()`：

- 保留 `excavationCount` 与 `excavationResets`；
- 保留永久解锁和遗物；
- 重置本轮其他资源。

当前 `reincarnate()`：

- 不复制 `excavationCount` 与 `excavationResets`，二者在新状态归零；
- 保留永久解锁和遗物；
- 保留全历史统计。

这部分与原版“退休保留、转生清零当前审计计数”已基本对齐。


引擎执行顺序建议：

## 16. 必须补充的验收测试

### 解锁与价格

- 1B 期权边界、产值边界、手持金币不足；
- 永久解锁不重复扣费；
- 第 1、2、3 次审计价格；
- 减费后价格和 `1.01` 下限；
- 当前计数与最高计数独立变化。

### 奖励与线索

- 35% 概率在固定 RNG 下可重复验证；
- 影响力数量公式与倍率；
- 六条线索只在对应次数出现且不重复；
- 第 `n` 颗红宝石次数与全历史不可重复领取；
- Survey 前不掉 Lore，Survey 后才进行 Lore 判定；
- Prestige 叠加时基础部门专属 Lore 的排除规则。

### 重置

- 退休保留当前审计计数；
- 转生和 Ascension 清零当前计数；
- 转生保留永久解锁、遗物、最高纪录和红宝石；
- Ruby Reset 价格、扣费与计数归零；
- Free Reset 开放条件、清空金币和 90% 惩罚；
- 退休／转生解除 Free Reset 惩罚；
- 任何重置都不能复活红宝石或一次性遗物。

### 部门链与统计周期

- 两条线索即可开放 Proof of Neutrality；
- 完整中立解锁物仍控制对应部门加入；
- Druid 只接受 This Game 1M 影响力；
- Faceless 接受 All Time 36 小时；
- Drow 只接受当前转生 10K 施法；
- R0～R2 每轮外交购买，R3+ 永久；
- 任务完成但未购买外交时，不开放高级部门货币与条约。

### UI 与存档

- 入口隐藏时无死按钮，恢复后状态可实时刷新；
- 资源不足按钮禁用，达到条件后自动启用；
- 存档迁移幂等，旧存档不会重复发奖励；
- 清除进度不会复活审计计数、遗物或红宝石。
