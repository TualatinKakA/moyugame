# 《无限工时》增量内容驱动游戏引擎：最优、高效与 Robust 架构设计

> 状态：目标架构与施工规范。
>
> 适用项目：`ttt2718/moyugame`，原生 JavaScript ES Modules、浏览器运行、无强制构建步骤。
>
> 目标：常规内容更新只增加声明式规则；启动时编译一次，游戏中以事务方式稀疏更新权威 State，只计算受影响的派生值和 UI。不得用“数据驱动”换取每帧全量解释规则。

## 1. 核心结论

本项目最适合的不是 ECS、完整事件溯源或每帧不可变 State 克隆，而是以下四件套：

1. **ContentGraph**：不可变内容定义及其启动期编译结果；是规则来源，不进存档。
2. **SaveState**：稀疏、可序列化、可迁移的唯一权威玩家状态；只保存事实，不保存派生值。
3. **Transactional Runtime**：Command／Tick → changedPaths＋Domain Events → 精确规则订阅 → 原子提交。
4. **RuntimeCache**：派生产值、条目状态、UI ViewModel 等可丢弃缓存；由 ContentGraph＋SaveState 重建。

必须同时满足：

- 普通新增设施、派系、法术、升级、Trophy、剧情，不修改引擎函数、UI 分支或存档字段。
- 任何 Tick 不全量遍历内容、不全量克隆 State、不全量序列化存档、不全量重建 DOM。
- 相同内容版本、初始 State、RNG Seed、Command 序列和 Tick 序列，必须得到相同状态哈希。
- 内容错误在启动期完整报告，不允许带着半套非法依赖静默运行。
- 所有持久变更可追踪、可验证、可迁移；所有一次性奖励幂等。

## 2. 需求、边界与明确取舍

### 2.1 必须支持的内容

- 建筑、普通升级、派系分层升级、Heritage；
- 法术、Spell Tier、Autocast；
- 派系、Alignment、Bloodline、Lineage、Artifact Set、Legacy 等选择与互斥；
- Research Points／Slots／Budget；
- Trophy、Achievement、Challenge、Artifact、Quest；
- 剧情触发、选项、奖励、待播队列和回看；
- Abdication／Reincarnation／Ascension、离线收益和存档迁移；
- 后续新增内容包，不要求预先知道具体条目。

### 2.2 不采用的技术路线

| 路线 | 不采用原因 |
| --- | --- |
| 每帧解释全部 JSON 规则 | 内容越多越慢，低端手机容易长任务 |
| 每帧深拷贝或结构化克隆 State | 分配、GC 和序列化成本高 |
| 完整事件溯源并回放全部历史 | 存档膨胀，长期存档启动慢；本项目不需要 |
| 所有数值都写入 State | 派生缓存膨胀且容易产生不一致 |
| 内容中嵌入任意 JavaScript／`eval` | 无法安全校验、预编译和自动生成测试 |
| 过早引入 Web Worker | 状态传输和同步复杂；先证明主线程预算不足再使用 |
| 一次性重写全部游戏 | 风险不可控，采用差分测试下的渐进替换 |

### 2.3 “零引擎修改”的真实边界

以下更新应零引擎修改：使用已注册资源、条件、效果、操作、事件和 UI Kind 的新内容。

出现前所未有的基础机制时，允许新增一个**通用原语**，例如第一种预算资源或第一种跨分支槽位。原语注册后，同类内容继续纯配置更新。禁止以“新机制”为由给单个条目写专属分支。

## 3. 总体结构与数据所有权

```text
Content Definitions（只读、独立更新）
        ↓ 启动时 validate + compile
ContentGraph（定义、规则函数、依赖索引、调度索引）
        ↓ 读取
Transactional Runtime ─────→ RuntimeCache（可丢弃）
        ↓ 稀疏修改                 ↓ 增量失效／重算
SaveState（唯一权威事实）         Generic UI ViewModel
        ↓ 防抖序列化               ↓ 最小 DOM Patch
Save Adapter                    DOM
```

所有权规则：

- 只有 CommandEngine 和 TickEngine 可以发起 State 事务。
- UI 不得直接修改 State，只能 dispatch Command。
- 剧情、成就、Trophy 不直接改资源，只提交 Action 到当前事务。
- Effect 计算不得修改 State；它只读取 State 并返回派生结果。
- ContentGraph 启动后冻结，运行中不热修改。
- RuntimeCache 不是事实来源，丢失后必须可完整重建。

## 4. 内容定义规范

### 4.1 通用定义结构

项目继续使用原生 JavaScript 数据对象和 JSDoc 类型，不强制引入 TypeScript 或构建工具。

```js
/**
 * 所有字段均为声明式数据；value 使用安全公式 DSL，不使用 eval。
 */
{
  id: "spell.fairy_chanting",
  kind: "spell",
  contentVersion: "base-v1",
  nameKey: "spell.fairy_chanting.name",

  era: { minR: 0, maxA: 4 },
  visible: { op: "factionAvailable", id: "faction.fairy" },
  unlock: { op: "always" },
  purchase: null,
  cast: {
    costs: [{ resource: "mana", amount: "1000" }],
    requires: [{ op: "online" }]
  },

  effects: [{
    group: "spell.fairy_chanting",
    phase: "buildingLocal",
    stat: "building.production",
    target: { type: "buildings", ids: ["farm", "inn", "blacksmith"] },
    operation: "multiplyPercent",
    value: { constant: 50000 },
    stacking: "multiply"
  }],

  grants: [],
  reactions: [],
  scope: "run",
  ui: { icon: "spell.fairy_chanting", panel: "spells" }
}
```

通用字段：

| 字段 | 规则 |
| --- | --- |
| `id` | 永久稳定、全局唯一；发布后不复用、不改语义 |
| `kind` | 决定通用 Command、Selector 和 Renderer，不允许任意新字符串 |
| `contentVersion` | 内容包版本，不等同于存档 schema |
| `era` | R／A 可用区间和显式移除规则 |
| `visible` | 可见谓词；与购买、施放条件分离 |
| `unlock` | 永久发现／资格谓词或反应结果 |
| `purchase` | 成本、前置、互斥、槽位；可空 |
| `effects` | 结构化效果，不写回 State |
| `grants` | 成功后授予的解锁、资源、法术来源等 Action |
| `reactions` | 监听事件／统计阈值并执行 Action |
| `scope` | `run`、`r`、`ascension`、`total` 或明确的自定义周期 |
| `ui` | 通用展示元数据，不包含专属渲染逻辑 |

### 4.2 条件 DSL

只支持注册过的操作符及 `all／any／not` 组合。每个条件必须声明静态依赖，供编译器建立订阅索引。

```js
{
  all: [
    { op: "reincarnationAtLeast", value: 16 },
    { op: "buildingOwned", id: "farm", value: 2250 },
    { op: "notOwned", id: "quest.enchanted_fields" }
  ]
}
```

编译结果包含：

```text
conditionId
compiledPredicate(context)
staticDependencies: ["R", "building.farm", "runOwned.quest.enchanted_fields"]
evaluationCostClass
sourceContentId
```

不得在运行时通过 `Function`、正则解析表达式或字符串拼接生成谓词。

### 4.3 成本、效果和 Action

成本：

```js
costs: [
  { resource: "coins", amount: { formula: "buildingUpgradeCost", args: ["1e6", "x"] } },
  { resource: "factionCoin.fairy", amount: "5000" }
]
```

效果必须包含：`group／phase／stat／target／operation／value／stacking`。效果组是缓存和失效的最小单位。

Action 只包括通用原语：

- `grantResource`、`grantUnlock`、`grantOwned`；
- `grantSpellSource`、`removeSpellSource`；
- `select`、`clearSelection`；
- `startTimer`、`cancelTimer`；
- `enqueueStory`、`markStoryCompleted`；
- `emitFact`；
- `scheduleTask`。

Action 必须可校验、可记录、可幂等化，不允许执行任意回调。

### 4.4 内容文件组织

```text
src/content/
  definitions/
    buildings.js
    factions.js
    spells.js
    upgrades.js
    trophies.js
    research.js
    stories.js
  packs/
    base.js
    r16-research.js
  index.js                 # 仅聚合领域数组；新增条目无需修改
  migrations/
    content-aliases.js
```

向已有领域数组追加定义时，`index.js` 不变。新增独立内容包只允许修改内容 manifest，不修改引擎。

## 5. SaveState：稀疏、权威、可恢复

### 5.1 推荐结构

```js
{
  schemaVersion: 4,
  contentVersions: ["base-v1", "r16-research-v1"],
  revision: 123,
  createdAt: 0,
  lastSave: 0,
  lastWallClock: 0,

  resources: { coins: "0", gems: "0", mana: "0" },
  buildings: { farm: 10 },
  stats: {
    run: { time: 0 },
    r: { time: 0 },
    ascension: { time: 0 },
    total: { time: 0, clicks: 0 }
  },

  permanentUnlocks: { "trophy.fairy_champion": true },
  owned: {
    run: { "upgrade.fairy-1": true },
    r: {},
    ascension: {}
  },
  spellSources: { "spell.fairy_chanting": { "faction.fairy": true } },
  selections: { bloodline: "bloodline.fairy", lineage: null, artifactSet: null },
  loadouts: { research: {}, mercenary: {} },
  timers: { spells: {}, tasks: {} },
  challenges: {},
  artifacts: {},
  story: { pending: [], completed: {}, rewarded: {}, choices: {} },
  rng: { seed: 0, streams: {} },
  quarantined: { unknownIds: {}, invalidValues: {} }
}
```

### 5.2 稀疏原则

- 未拥有、未解锁和默认值不生成字段。
- 不为每个新条目向 State 添加专属布尔值。
- 对象用于持久 JSON；启动后可建立 Map／整数索引作为 Runtime 镜像。
- `revision` 单调递增，用于缓存和保存冲突检测。
- 派生产值、可见状态、DOM 状态、条件函数、依赖图全部禁止入档。

### 5.3 状态不变量

每次事务提交前检查受影响的不变量：

- 资源为有限、非负、规范数值；
- 同一购买作用域内 ID 不重复扣费；
- Selection 属于允许集合且不违反互斥；
- Loadout 不超过槽位和预算；
- Timer 时间和任务 ID 合法；
- Story rewarded 必须是 completed 的合法子集或明确允许的例外；
- 所有 changed ID 必须存在于 ContentGraph 或迁移／隔离记录中。

## 6. 启动与内容编译

### 6.1 启动顺序

```text
读取全部内容定义
→ 逐条 Schema 校验
→ 全局 ID、引用、依赖和周期校验
→ 数值／条件／公式编译
→ 建立事件、统计、效果、UI 和任务索引
→ 冻结 ContentGraph
→ 读取并校验存档
→ 顺序执行 schema migration 和 content alias migration
→ 创建稀疏 SaveState
→ 全量构建一次 RuntimeCache
→ 全量渲染一次 UI
→ 进入增量运行
```

任何阶段失败都要有明确错误码和内容 ID。非法新内容包不得静默跳过；开发环境直接阻止启动，生产环境回退到最后一次已知良好内容清单。

### 6.2 启动期全局校验

必须报告全部错误而非遇到第一个即停止：

- 重复 ID、非法 Kind、未知操作符；
- 前置、grants、图标、剧情跳转和资源引用不存在；
- 非声明式循环依赖；
- 成本和效果出现负数、NaN、Infinity 或非法目标；
- 同一内容同时声明冲突的 reset scope；
- Reaction 没有触发源或 Action 没有目标；
- 永久奖励缺少幂等键；
- UI Kind 未注册；
- 条件依赖无法索引且会退化为 Tick 全量扫描。

### 6.3 索引集合

ContentGraph 至少包含：

```text
definitionsById
integerIdByString / stringIdByInteger
commandHandlerByKind
selectorByKind
rendererByKind

eventSubscribers[eventType] -> reactionIds
statSubscribers[statPath] -> thresholdRuleIds
timerSubscribers[timerKind] -> taskIds
visibilityDependents[path] -> contentIds
purchaseDependents[path] -> contentIds

effectDependencies[path] -> effectGroupIds
effectOrderByPhase
unlockReverseGraph[sourceId] -> targetIds
migrationAlias[oldId] -> newId
```

热路径使用整数 ID；字符串 ID 只用于内容边界、存档、日志和调试。

## 7. 对外运行接口

建议只暴露一个 GameRuntime 门面：

```js
const game = createGameRuntime({
  content,
  saveAdapter,
  clock,
  numericAdapter,
  seed,
  mode: "production"
});

await game.start();
game.dispatch({ type: "purchase", id: "upgrade.fairy-1" });
game.tick(deltaSeconds);
game.select(selector, args);
game.subscribe(listener);
await game.save({ reason: "debounce" });
game.stop();
```

禁止绕过门面直接调用内部购买函数或修改 State。测试可注入 Clock、RNG、SaveAdapter 和 NumericAdapter，确保无真实时间、localStorage 或随机数依赖。

## 8. Command 与事务管线

### 8.1 事务生命周期

```text
接收 Command
→ 参数与 Command 类型校验
→ beginTransaction(state)
→ 读取当前 RuntimeCache／必要时局部重算
→ 检查 visible／unlock／purchase／slot／mutex／cost
→ 记录旧值到 Undo Journal
→ 扣费并写入稀疏 State
→ 执行 grants，产生 Domain Facts
→ 处理内部 Reaction Queue 至不动点
→ 校验受影响的不变量
→ 提交 changedPaths、newRevision 和事件列表
→ 精确失效 RuntimeCache
→ 通知 UI
→ 按策略防抖保存
```

事务失败时通过 Undo Journal 回滚本次旧值，不克隆整个 State。事务完成后 Undo Journal 即丢弃，不进入存档。

### 8.2 事务上下文

```js
{
  state,
  changedPaths: Set,
  facts: [],
  reactionQueue: [],
  undo: [],
  grantedOnce: Set,
  dirty: {
    effectGroups: Set,
    selectors: Set,
    timers: Set
  },
  diagnostics: {
    evaluatedRules: 0,
    emittedFacts: 0,
    maxQueueDepth: 0
  }
}
```

### 8.3 原子性和重入

- 扣费、owned、grants、Trophy 和剧情奖励必须在同一事务成功。
- Reaction 不得同步开启嵌套事务，只能向当前队列追加 Action。
- 队列按 `priority → content integerId → sequence` 确定性排序。
- 每批设置合理反应上限；超限视为内容循环或引擎错误，回滚并报告完整事件链。
- 永久奖励以 `rewardId` 去重；重复事件不得重复发奖。
- UI 通知和日志在提交后发送，不能观察半提交状态。

### 8.4 保存失败策略

普通 Command 可以先提交内存并防抖保存；保存失败必须显示“未保存”、保留 dirtySave 标记并自动重试，不得静默提示已保存。

首通剧情、稀有付费资源等被明确标为 `persistence: critical` 的操作使用同步关键保存策略：先序列化候选 State 并写入保存槽，成功后发布提交；失败则回滚事务。不得把所有点击都升级为关键保存。

## 9. Domain Facts 与 Reaction Engine

### 9.1 事实而非任意回调

事件使用过去时、可序列化数据：

```js
{
  type: "spell.cast",
  sequence: 91,
  payload: { spellId: "spell.fairy_chanting", tier: 1, free: false },
  changedPaths: ["stats.run.spellsCast", "stats.total.spellsCast"]
}
```

核心事实包括：购买、施法、解锁、建筑变化、Trophy 获得、派系加入、挑战完成、退休、转生、剧情完成和离线结算。

### 9.2 精确订阅

- `spell.cast` 只唤醒订阅该事件或该 spellId 的规则。
- `stats.total.clicks` 变化只唤醒订阅该路径的阈值规则。
- 阈值规则使用旧值／新值跨越判断：`old < threshold && new >= threshold`，避免重复触发。
- 时间规则注册到 Scheduler，不在 Tick 中轮询全部时间条件。
- 不可索引的动态条件必须在启动期被警告；热路径禁止全量条件集合扫描。

### 9.3 Trophy、Challenge 和 Achievement

Trophy 达成只写永久事实；同名 Upgrade 的可见和购买由依赖图派生。Challenge 完成、Achievement 状态和奖励使用同一事务与幂等机制，不再维护另一套购买状态机。

### 9.4 剧情

剧情是 Reaction 的一种：

```text
Domain Fact
→ Story Trigger 条件判断
→ 写入持久 pending 队列并去重
→ Story UI 按优先级播放
→ 玩家选择 dispatch StoryChoiceCommand
→ 校验分支条件
→ 通过 Action 发奖／解锁
→ 标记 completed 与 rewarded
```

剧情演出失败不撤销已完成游戏操作；pending 保留。回看只播放内容，不重新执行 Action。默认不暂停模拟，只有显式 `pause` 才暂停指定时钟域。

## 10. Tick 与 Scheduler

### 10.1 固定节拍

主循环保持简单，建议 200ms 一次模拟；渲染按 dirty 通知执行，而不是强制每 Tick 全刷。

```text
读取并夹紧 deltaTime
→ 批量增加四层时间统计
→ 读取 Tick 开始时的相关派生数值
→ 结算资源生产和 Mana
→ 执行到期的 Timer／周期任务
→ 执行 Autocast Command（进入当前事务队列）
→ 推进法术持续时间、冷却和计数器
→ 批量处理 changedPaths 与 Domain Facts
→ 原子提交
→ 每个 Effect Group 最多重算一次
→ 每个 UI Selector 最多失效一次
```

同一 Tick 内多个系统重复触碰同一路径，只合并成一次缓存失效和一次 UI 通知。

### 10.2 时间边界

顺序是规则的一部分，必须固定并有边界测试。推荐：Tick 开始快照结算本 Tick 产出，然后处理到期 Timer；因此法术在某 Tick 内到期，其效果覆盖该 Tick，下一 Tick 不再计入。Autocast 新施法术从下一 Tick 参与产出，除非 Command 明确指定立即结算。

### 10.3 Scheduler

每个周期系统只注册下一到期时间：

```text
timerMinHeap / bucketWheel
nextDueAt
taskId
repeatRule
```

Tick 只弹出 `dueAt <= now` 的任务。禁止为每个 Green Fingers、Spell 或 Trophy 在 Tick 中执行一次全表 `if`。

### 10.4 后台和离线

页面隐藏时保存并停止依赖高频率的 UI 工作。回到前台按离线管线处理，不补跑大量 200ms Tick。负 delta、系统时间回拨和异常长 delta 必须有单独策略与日志。

## 11. 派生数值与缓存

### 11.1 三类缓存

| 缓存 | 典型内容 | 失效条件 |
| --- | --- | --- |
| Content Static | 编译条件、成本公式、静态依赖 | 仅启动／内容版本变化 |
| Loadout Snapshot | 当前派系、研究、Legacy、永久 Trophy 的静态 Modifier | 购买、选择、解锁、重置 |
| Dynamic Snapshot | 当前产出、Mana、动态公式结果 | 相关统计、Timer、资源或动态目标变化 |

不得再用整个 State 的 `JSON.stringify` 作为每次计算的缓存指纹。缓存键由 `revision＋changedPaths＋依赖元数据` 决定。

### 11.2 Effect DAG

Effect Group 按 phase 和依赖组成 DAG：

```text
raw
→ assistants
→ mana
→ buildingBase
→ buildingLocal
→ global
→ factionCoin
→ click
→ utility
```

新增 phase 前必须证明无法复用现有阶段。禁止未声明的双向依赖；确需迭代的机制必须有显式最大迭代次数、收敛检查和确定性顺序。

### 11.3 局部失效

- 购买建筑只失效该建筑数量、相关建筑产出和依赖全局建筑数的 Effect Group。
- 点击只更新点击统计及其订阅者；没有点击依赖的法术和 Trophy 不重算。
- 切换 Bloodline 只失效血脉、相关选择和依赖血脉的效果。
- 永久 Trophy 解锁不失效本轮无关研究 UI。

每次事务结束统一处理 dirty 集，避免同一事务内反复重算。

### 11.4 Snapshot 只读

开发环境对 Snapshot 深冻结；生产环境至少保持约定不修改。Effect Aggregator 返回新派生对象，不得把中间 Modifier 写回 SaveState。

## 12. 数值系统

### 12.1 NumericAdapter

所有资源、成本和公式通过统一数值接口，禁止内容层直接依赖 JavaScript Number 的无限范围假设。

```text
add / sub / multiply / divide
pow / log / ln / sqrt / floor / ceil
compare / min / max
isFinite / isNonNegative
serialize / parse
```

### 12.2 最优实现取舍

- 时间、次数、建筑数量等可证明处于安全整数范围的值使用 Number，并设置边界断言。
- Coins、Gems、Faction Coins、超大成本及指数公式使用高精度或对数大数实现。
- 持久大数使用规范字符串，禁止 JSON NaN／Infinity。
- 热路径不重复解析数字字符串；编译期和载入期完成解析，运行时复用数值对象。
- 不用全局高精度运算包装所有简单计数器，避免无收益开销。

### 12.3 公式安全

公式编译为白名单 AST 或预编译函数；只允许注册变量和数学操作。非法变量、非有限结果、除零策略和溢出必须在启动或事务边界明确报错。

## 13. Selector、状态原因码与 Generic UI

### 13.1 统一条目状态

```text
HIDDEN_SYSTEM
HIDDEN_ERA
HIDDEN_PREVIOUS_TIER
LOCKED_REQUIREMENT
UNAVAILABLE_CONTEXT
AVAILABLE_UNAFFORDABLE
PURCHASABLE
OWNED
SELECTED
BLOCKED_EXCLUSIVE
SLOT_FULL
NEED_RESOURCE
NEED_ASCENSION
```

Selector 返回：

```js
{
  id,
  status,
  reasons: [{ code, args }],
  costs,
  progress,
  viewModel
}
```

价格不足不能使普通已解锁条目重新 HIDDEN。CommandEngine 与 Selector 使用同一编译规则，防止“UI 说能买、引擎拒绝”。

### 13.2 UI 更新

- 启动全量渲染，之后按 dirty contentId 做最小 DOM Patch。
- 长 Trophy／Research 列表分页或虚拟化，屏幕外节点不做实时状态刷新。
- 不在 Tick 中重建整个面板 `innerHTML`。
- 图标、文本、按钮 disabled 和进度条分别缓存旧值，只写变化属性。
- Renderer 只处理 Kind；禁止出现 `if (id === "某具体法术")`。

### 13.3 交互响应

点击后立即执行 Command，不等待下一 Tick。UI 可以乐观显示按压反馈，但资源、owned 和奖励只以事务提交结果为准。

## 14. 存档、迁移与恢复

### 14.1 SaveAdapter

接口：`load／save／backup／remove／listSlots`。生产使用 localStorage，测试使用内存和故障注入 Adapter。

推荐主槽＋上一良好备份槽：

```text
读取主槽
→ JSON、schema、数值和校验和验证
→ 失败则读取上一良好备份
→ 两槽均失败则保留原始字符串供导出，不静默覆盖
→ 新游戏必须经用户明确确认
```

localStorage 单键写入具有同步性，但不能替代备份、异常处理和配额失败处理。

### 14.2 保存节流

- 普通状态变化只设置 `saveDirty`。
- 15 秒或重要节点防抖保存；页面隐藏、退出和手动保存立即执行。
- 一次保存只序列化一次，不在每个 Tick 做全量 JSON。
- 保存失败保留内存 State 和未保存提示，指数退避重试。

### 14.3 两类迁移分离

**Schema Migration**：State 结构变化，按 `v3 → v4 → v5` 顺序执行纯函数，不能跳版本猜测。

**Content Migration**：条目改名、拆分或合并，通过稳定 ID alias 和显式转换处理。

```text
读取旧档
→ 保留原始备份
→ schema migrations
→ content alias／value migrations
→ 完整校验
→ 隔离未知 ID，不随意删除付费或稀有进度
→ 返回新 State＋MigrationReport
```

迁移函数必须可重复执行到同一结果，且不得触发剧情、奖励或随机数。

## 15. 离线结算

### 15.1 不补跑固定 Tick

离线按事件时间分段，而非循环 200ms：

```text
计算离线时长和上限
→ 找到下一法术到期／周期任务／Autocast 变化点
→ 在该时间段内按稳定产率结算
→ 推进到下一事件点并更新派生值
→ 直到离线时间结束或达到安全迭代上限
→ 产生一次 offline.settled 事实和汇总报告
```

### 15.2 精确与近似的边界

- 固定产率、Mana 恢复和确定性周期任务应精确分段。
- 随机掉落使用可复现 RNG 和批量概率结算，保证同 Seed 可重放。
- 复杂在线限定机制不得伪造精确结果；只能按原版规则关闭或显式标记允许的近似。
- 达到迭代上限时停止并报告，不得卡死启动。
- 离线 Trophy／剧情只根据实际离线规则触发，不默认补播在线限定条件。

## 16. Robustness：错误、确定性与安全

### 16.1 错误分级

| 级别 | 示例 | 处理 |
| --- | --- | --- |
| Content Fatal | 重复 ID、未知公式、非法依赖环 | 开发环境阻止启动；生产回退已知良好内容 |
| Transaction Reject | 钱不够、槽满、派系错误 | 正常拒绝，返回原因码，不记错误日志洪峰 |
| Transaction Fatal | 不变量破坏、反应队列超限 | 回滚本事务，记录事件链和内容 ID |
| Save Recoverable | 配额、临时写入失败 | 保留 dirtySave、备份和重试 |
| Save Fatal | 主备均损坏 | 停止覆盖原档，提供导出和明确重开选择 |
| UI Isolated | 图片、单个面板渲染失败 | 保留游戏模拟和存档，显示可恢复错误 |

### 16.2 确定性

- RNG 按领域分流，例如 `drops／spells／events／cosmetics`，避免新增一个视觉随机调用改变掉落序列。
- 每个 Stream 保存 Seed 和调用计数；事务回滚时一并回滚。
- 所有事件排序、Effect 叠加顺序和 Story 优先级均显式定义。
- 禁止业务逻辑直接调用 `Math.random()` 或 `Date.now()`；通过注入接口。
- 浮点格式化不参与状态哈希；使用规范化持久值。

### 16.3 诊断

开发模式记录有限环形日志：Command、changedPaths、Fact、Reaction、dirty Groups 和耗时。生产默认关闭详细日志，只保留错误摘要，防止日志本身造成内存和性能问题。

提供调试快照：

```text
contentVersion / schemaVersion / revision
stateHash / rngStreams
cacheHits / cacheMisses
lastTransactionRules / queueDepth / duration
saveDirty / lastSaveError
```

## 17. 高效实现规范

### 17.1 热路径禁止事项

- 禁止全量 State 深拷贝、结构化克隆或 JSON 指纹。
- 禁止每 Tick 全量扫描 Trophy、可见条件、购买条件和 Research。
- 禁止在热路径解析公式、数字字符串、正则和 ID 前缀。
- 禁止同一事务内同一 Effect Group 重复重算。
- 禁止全量 DOM 重建和屏幕外节点持续更新。
- 禁止每 Tick 保存完整存档。
- 禁止为了少量变化重建整个 ContentGraph。

### 17.2 推荐优化顺序

1. 用依赖订阅和 changedPaths 消除无效计算。
2. 合并同一 Tick 的失效和 UI 更新。
3. 用整数 ID、Set 和预编译闭包降低判断成本。
4. 对超大列表虚拟化。
5. 依据 Profile 优化真实热点，不预先引入 Worker、复杂 BitSet 或自定义内存池。

只有数据证明简单结构不足时，才引入 BitSet、TypedArray 或 Worker；这些不是架构成立的前提。

### 17.3 性能预算（验收目标，不是未测承诺）

以生产模式、目标中低端手机、典型后期存档为基准：

| 指标 | 目标 |
| --- | --- |
| 常规 200ms Tick P95 | < 10ms |
| 普通购买到 UI 提交反馈 P95 | < 50ms |
| 单次前台主线程长任务 | 尽量 < 50ms |
| 15 秒自动保存 P95 | < 50ms，失败可恢复 |
| 当前内容量启动编译＋首屏 | < 1.5s |
| 5 倍内容压力测试 | 不出现随 Tick 全量增长的明显退化 |
| 长时间运行 | 无持续内存增长、无 Reaction 队列堆积 |

必须在 CI 或固定基准机记录结果，不以开发机主观“很流畅”为验收。

## 18. 自动校验与测试体系

### 18.1 每条定义自动生成测试

所有条目至少覆盖：

1. 系统／R／A 不满足时隐藏；
2. 可见但条件不足；
3. 条件满足但资源不足；
4. 可购买／可选择；
5. 原子扣费且 owned 只写一次；
6. grants 和反向依赖正确；
7. 互斥、槽位和预算；
8. Abdication／Reincarnation／Ascension 后保留正确；
9. 未知旧 ID 的迁移或隔离；
10. 不依赖价格来决定普通条目的可见性。

### 18.2 引擎测试

- Command 接受、拒绝、回滚和重入；
- Reaction 顺序、幂等、环检测和队列上限；
- Tick 边界、Timer、Autocast 和同 Tick 多次失效；
- Effect DAG 顺序、非法环和非有限值；
- 保存失败、备份恢复、配额失败和中断迁移；
- 负 delta、时钟回拨和超长短离线；
- 剧情 pending、回看、奖励去重和关键保存失败；
- 相同 Seed＋Command＋Tick 的状态哈希重放一致。

### 18.3 属性与模糊测试

随机生成合法购买／重置／施法序列，持续检查：资源不为负、不重复扣费、Selection 合法、槽位不超限、派生 Snapshot 可从 State 重建。

对存档 JSON、旧 schema、未知 ID、非法数值和截断写入做模糊测试，确保不会静默清档。

### 18.4 差分迁移测试

旧引擎替换期间，同一随机操作序列同时运行 Legacy 和 New Runtime，对比资源、统计、解锁、产出和重置结果。已确认的旧 Bug 以白名单记录预期差异，不能随意忽略全部差异。

### 18.5 性能回归

固定内容包、固定 Seed、固定后期存档，记录启动、Tick、Command、保存和内存。性能预算失败应与功能测试失败一样阻止合并。

## 19. 推荐模块划分

```text
src/

    definitions/          # 常规更新只改这里
    packs/
    migrations/
    schema.js

  systems/
    content-registry.js   # validate、compile、freeze、索引
    state.js              # 稀疏 State、invariants
    numeric.js            # NumericAdapter
    commands.js           # Command 路由和事务
    transaction.js        # Undo、changedPaths、commit
    facts.js              # Domain Fact 类型与队列
    reactions.js          # Trophy／Challenge／Story reactions
```

## 20. 渐进替换旧引擎

### 阶段 0：冻结行为基线

- 为现有购买、施法、派系、挑战、退休、剧情和迁移补充 Characterization Tests。
- 记录当前性能基准和已知 Bug，不在迁移期同时做大规模数值改版。

### 阶段 1：引入可替换底座

- Clock、RNG、NumericAdapter、SaveAdapter、Sparse State 和 Transaction。
- 旧逻辑暂时通过 Adapter 调用，不改变玩家可见行为。

### 阶段 2：ContentGraph 与双读校验

- 把现有配置转换为统一 Schema。
- 启动时编译，建立定义和依赖索引。
- 旧硬编码规则与新 Selector 双读，对差异报警。

### 阶段 3：按域迁移 Command

推荐顺序：Misc Upgrade → Building Upgrade → Faction Upgrade → Spell／Autocast → Challenge → Research／选择系统。

每迁移一个域就删除对应旧购买分支，不允许永久保留两份权威规则。

### 阶段 4：派生缓存和 Generic UI

- 用 changedPaths 替代全 State JSON 指纹。
- UI 改为 Selector＋Kind Renderer，删除具体 ID 的可见性分支。

### 阶段 5：Story／Achievement／Trophy 统一 Reaction

- 保留现有事件、条件和剧情状态优点，接入同一事务、幂等奖励和持久 pending。
- 验证保存失败、回看和重置边界。

### 阶段 6：离线、恢复和性能收尾

- 事件时间分段离线结算。
- 主备恢复、故障注入、压力测试和性能预算验收。
- 删除 Legacy Runtime 和临时双读路径。

## 21. 常规内容更新 Loop

以新增 Trophy 和法术为例，只修改内容定义：

```text
写入 Trophy：事件／统计阈值、永久奖励 ID、同名 Upgrade 成本和效果
写入 Spell：来源、Mana、Duration、Tier、效果和 UI 元数据
写入关联 grants／reactions
→ 启动自动校验和编译
→ 自动出现在依赖图与对应面板
→ 条件达成后自动解锁
→ 通用 Command 处理购买／施法
→ 稀疏 State 自动保存新 ID
→ 自动执行生成测试、迁移测试和性能回归
→ 发布
```

不需要：修改 Tick、添加专属购买函数、添加 State 布尔字段、添加 UI `if`、修改自动保存格式或手写一套重复基础测试。

## 22. 最终验收标准

只有同时满足以下条件，才能称为目标引擎完成：

### 内容性

- 当前所有建筑、派系、法术、升级、挑战、剧情和成就均由统一定义驱动。
- 常规新增内容不改引擎、UI 和 State Schema。
- 原版关系清单中的可见／购买／解锁／互斥／scope 均可表达。

### 正确性

- Command 原子、Reaction 幂等、顺序确定、RNG 可重放。
- UI 与 Command 使用同一规则，无双重权威。
- 派生 State 可完全重建，旧档迁移不会静默丢进度。
- 剧情奖励、首通 Trophy 和重置边界通过故障注入。

### 性能

- Tick 无内容全表扫描、State 全克隆、全量 JSON 指纹或全量 DOM 重建。
- 当前与 5 倍内容量均通过性能预算。
- 长存档运行无持续内存增长和队列堆积。

### 可维护性

- 启动校验能定位到内容 ID 和字段。
- 所有新原语有通用用途、Schema、测试和文档。
- Legacy 硬编码购买与可见分支已删除，不存在双套规则。

---

**最终不变量：**ContentGraph 描述“世界有什么规则”，SaveState 记录“玩家实际发生了什么”，RuntimeCache 回答“当前计算结果是什么”。三者不得互相冒充。常规更新只改 ContentGraph 来源，游戏过程只做稀疏事实变更和精确派生失效。
