# 《无限工时》设施与派系 SVG 视觉设计规范

本文只记录长期有效的底层制作、命名和复用规则，不记录制作进度或当前完成状态。

## 1. 总体原则

- 不为每项升级分别创作独立插画。先确认唯一母版，再按固定规则生成衍生图。
- 设施编号升级：**主体识别设施，右上角数字识别段数**。
- 派系普通升级：**母题识别部门，铜银金识别 Tier，母题数量识别项内位置**。
- 部门身份、协议、普通升级、法术和 Trophy 的视觉语义不得混用。
- 图形采用低多边形现代职场物件，不使用奇幻原名的图形直译。

## 2. 通用技术规范

- 画布统一为 `64 × 64`，使用 `width="64"`、`height="64"`、`viewBox="0 0 64 64"`。
- 透明背景，无额外卡片底和装饰外框。
- 用实心多边形和明暗块面表现结构、厚度和轻微透视。
- 内部功能线可以使用方端、斜接的实色线条，不把整幅图变成线稿。
- 禁止 `<image>`、Base64 位图、外部图片、外部 CSS、脚本、动画、滤镜和渐变元素。
- 每张 SVG 都有 `<title>` 与 `<desc>`；标题包含当前条目名称。
- 除协议合约数字外，不使用系统字体；设施数字必须使用矢量路径。

通用色板：

| 用途 | 颜色 |
| --- | --- |
| 深色结构 | `#333B3A`、`#46504F` |
| 中间灰 | `#697473`、`#899492`、`#AAB8B8` |
| 浅色结构 | `#D9E2E2`、`#EEF3F2` |
| 棕色结构 | `#A5684A`、`#835039`、`#65402F` |
| 功能强调 | `#C4764D`、`#DF9A6C` |
| 自动化辅助 | `#91B77A`、`#B4CDA3` |

## 3. 设施与设施升级

### 3.1 一设施，一主体

设施本体和全部 23 档编号升级共享完全相同的主体 `<g>`。路径、颜色、尺寸、位置和透视不得变化。

- 本体无徽章。
- 每档编号升级只追加对应的 `upgrade-tier-N` 徽章组。
- 不得按档位更换道具、整体改色、复制主体或添加其他刻度。
- 修改主体后，必须重新生成全部 23 档升级。

### 3.2 数字徽章

徽章固定在右上角，双位数可以向左扩展，但右缘、高度和切角语言一致。数字是主要信息，颜色只是辅助信息。

| 段数 | 主色 | 高光 | 暗部 |
| --- | --- | --- | --- |
| 1 | `#B97852` | `#D49A73` | `#8E563C` |
| 2 | `#C3CECE` | `#EEF3F2` | `#8E9C9C` |
| 3 | `#E7CA74` | `#F5E4A8` | `#B09552` |
| 4～22 | 按公式插值 | 按公式插值 | 按公式插值 |
| 23 | `#A875D8` | `#D3B9EF` | `#74509A` |

第 4～23 段使用离散纯色。令 `t = (N - 3) / 20`，在 sRGB 各通道线性插值并四舍五入：

- 主色：`#E7CA74 → #A875D8`。
- 高光：`#F5E4A8 → #D3B9EF`。
- 暗部：`#B09552 → #74509A`。

数字统一使用 `#252A27`。

### 3.3 合集与独立 Bonus

- `<building-id>-collection.svg` 复用设施主体，只追加 `purchased-upgrades-arrow` 红色向上箭头。
- 合集不是购买条目，也不是第 24 段，不得显示数字 `24`。
- Hall Bonus 等独立 Bonus 不属于编号升级，不得接续成第 24～29 段，也不得只替换数字。

## 4. 部门与派系图标

### 4.1 六部门核心母题

所有母题均为纯矢量。同一部门的身份、协议、普通升级和衍生功能图从同一母版派生。

| 部门 ID | 母题 | 核心颜色 |
| --- | --- | --- |
| `fairy` | 微倾纯白翻盖笔记本电脑 | 灰白机身，屏幕色块 `#DF9A6C`／`#D9E2E2` |
| `goblin` | 木框金珠精算算盘 | 木框 `#A5684A`／`#835039`／`#65402F`，算珠 `#E7CA74`／`#DF9A6C` |
| `elven` | 机械键盘键帽 | `#EEF3F2`／`#D9E2E2`，指示条 `#91B77A` |
| `angel` | 黄铜晨会桌铃 | `#F5E4A8`／`#E7CA74`／`#DF9A6C` |
| `undead` | 冷战立式双盘磁带机 | 机身 `#46504F`／`#333B3A`，磁带盘 `#EEF3F2`／`#D9E2E2` |
| `demon` | 高压压力表与截止手轮阀门 | 表盘 `#EEF3F2`，红橙区 `#DF9A6C`／`#C4764D` |

不得因升级影响某设施就把派系图标换成该设施，也不得跨部门借用母题。

### 4.2 部门身份与协议

- `factions/{dept}.svg`：部门身份与加入入口。只显示完整原色母题，不带合约角标。
- `factions/{dept}-pact.svg`：协作协议。
- `factions/{dept}-alliance.svg`：战略协议。

只有 Pact／Alliance 在右下角叠加合约。协议主体使用：

```xml
<g transform="translate(-2.5, -2.5) scale(0.92)">…</g>
```

合约固定在 `x: 34～62, y: 25～60`，使用折角纸页、右下 1px 硬边投影、三条横线和等宽粗体数字。数字使用 `Consolas, monospace`、`font-size="20"`、`font-weight="700"`。

| 协议 | 数字 | 纸面 | 描边 | 折角亮面／暗部 |
| --- | ---: | --- | --- | --- |
| Pact | 2 | `#C9D1D9` | `#38424D` | `#E6ECF2`／`#8C99A6` |
| Alliance | 3 | `#E7CA74` | `#5E4B28` | `#F4E4A9`／`#B99545` |

### 4.3 部门 1～9 项普通升级

文件为 `factions/{dept}-1.svg`～`factions/{dept}-9.svg`。

| 编号 | Tier | 色盘 |
| --- | --- | --- |
| 1～3 | 铜 | `#E6B38E`／`#D49A73`／`#B97852`／`#8E563C` |
| 4～6 | 银 | `#EEF3F2`／`#D9E2E2`／`#C3CECE`／`#8E9C9C` |
| 7～9 | 金 | `#F5E4A8`／`#E7CA74`／`#D1B15C`／`#B09552` |

计算规则：

```text
tier    = floor((N - 1) / 3) + 1
variant = (N - 1) % 3 + 1
```

阵列规则：

| Variant | 缩放 | `<g>` 绘制顺序与变换 |
| --- | --- | --- |
| 1 | `0.95` | `translate(1.5, 1.5) scale(0.95)` |
| 2 | `0.76` | 先 `translate(12, 2.5) scale(0.76)`，后 `translate(1.5, 8.5) scale(0.76)` |
| 3 | `0.68` | 先 `translate(9.5, -0.5) scale(0.68)`，再 `translate(18, 14) scale(0.68)`，最后 `translate(1.5, 16) scale(0.68)` |

同一阵列中的副本同尺寸、同颜色、同母版。后绘制者在上层，不得旋转、镜像、换道具或添加数字角标。

## 5. 衍生图标与复用关系

- **Heritage**：牛皮纸线装手册，封面嵌 `translate(12, 17) scale(0.35)` 原色部门母题。
- **Champion Trophy**：直接复用对应 Heritage 画面，只允许更改标题和描述。
- **部门 Exchange**：托盘、双向箭头和 `translate(15.5, 16.5) scale(0.52)` 原色母题；调拨行实际显示该图。
- **Royal Market 总入口**：使用通用托盘与双向箭头，不借用单一部门母题。
- **基础法术**：使用 `spells/<spellID>.svg`。
- **法术 Trophy／同名 Upgrade**：二者使用完全相同的画面。
- **升级后的技能**：购买对应 Upgrade 后，快捷技能和全部技能列表直接切换到该 Trophy 图。技能仍保留原 ID 与名称。
- **Secret Trophy／同名 Upgrade、Assistant Trophy／对应 Upgrade**：共享画面，但分别保留条目文件、配置和状态。

复用的对象是母版和画面模板，不是取消条目身份。修改母版后，所有受影响的衍生图必须全量重新生成。

## 6. 命名、归档与检查

### 6.1 命名

活动内容默认使用：

```text
assets/images/content-icons/<类别目录>/<条目ID>.svg
```

例如 `fairy-1.svg`、`fairy-pact.svg`、`good.svg`、`evil.svg`。以运行时条目 ID 为准，不使用 Misc 对照名或历史 Tier 组合名代替。

设施编号升级和合集保留专用规则：

```text
upgrades/<building-id>-tier<N>.svg
upgrades/<building-id>-collection.svg
```

### 6.2 归档

- 被替换的旧图按原路径和文件名保存到 `assets/images/legacy/`。
- 活动内容不得继续引用 legacy 或旧 Tier 组合命名。
- 共享占位图和仍被其他功能使用的共享 PNG 不得误删。

### 6.3 检查权限

默认只进行 XML、路径、标题、矢量元素、母版一致性和引用关系等静态检查。

**任何浏览器验收都必须先询问并获得用户同意。** 未经同意，不得启动浏览器、本地服务器、浏览器测试或截图流程，也不得把浏览器验收当作默认完成条件。
